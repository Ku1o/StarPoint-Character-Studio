# 不懂代码也能开始制作角色

适用于 0.8.2 预览版。配套工具见 [v0.8.2 预览版本入口](https://github.com/Ku1o/StarPoint-Character-Studio/releases/tag/v0.8.2)与 [Windows ZIP](https://github.com/Ku1o/StarPoint-Character-Studio/releases/download/v0.8.2/StarPoint-Character-Studio-0.8.2-Windows.zip)。安装、资源包和升级说明见[完整使用说明](USER_GUIDE.md)。

最简可用路径：新建角色 → 写角色和技能想法 → 选择或上传已有素材 → 详细说明缺项 → 保存并导出工程。即使暂时没有图片、配音或确定的技能数值，也能交出可继续制作的草稿。

## 1. 新建或打开工程

首页选择「原创角色」即可开始，不要求官方资源包。已有官方素材时可「基于角色模板」新建；已有可编辑工程则使用「打开工程 / 参考包」。参考包保留参考角色及资源来源，模板新建后复制为独立工程，编辑不会改动模板库。

新建工程先进入角色设定。点击侧栏「开始与进度」，打开「从这里开始制作角色」步骤页，其中提供角色设定、图片、动作、玩法、特效、声音、缺项和交接入口。可以跳到已有材料的步骤。

## 2. 先写角色和玩法

0.8.2 中，“从工程中选择复用参考”提供动作/特效预览和声音试听。先看或听，再点“选用这个参考”；关闭或返回会停止播放，原素材不会变化。复杂技能或召唤的完整战斗行为仍需制作方核对，可以先选择其动作、特效或声音部分。

接入预览里的每个制作步骤都能保存进度和说明。可选“待处理、处理中、待协助、准备好待验”；准备好时说明已提供的资料或结果，继续交给制作方验证。改了方案或参考后会重新待核，旧记录可展开查看并随工程导出，不需要填写代码。

复杂技能、特殊能力或形态、召唤物可以用中文填写外观、数量、寿命、行为、声音时点和结束恢复规则。预览会分别显示已经说明的内容、还可补充或申请协助的内容，以及制作方接下来核对的步骤；填完信息不会把游戏接入自动标为完成。

在复杂玩法中点击“从工程中选择复用参考”，按名称选择真实已有的技能、动作、特效或声音。它只记入参考选择并核对来源，不替换原技能或原稿；参考不存在、原文件变化或动态行为未证明时继续待核。没有合适候选时，仍可写参考角色或申请协助。

“增加技能槽”卡片填写正百分比，最多100%，选择明确的触发与角色对象；数值按基础最大技能槽计算，沿游戏原有获取限制。先预览、勾选后才追加实际条目；持续充能、固定量、特殊叠加等需求保留交接，不会猜成这个选项。

在「角色是谁」写角色名、称号、属性、职责和种族。暂时不知道的内容可以稍后到填写包申请协助。

在「角色能做什么」选择主动技能、队长技、强化弹射（PF）或能力槽，写名称和想要的行为。可以直接用中文，例如“施放技能后攻击前方敌人，想要三次命中，倍率请制作方协助确定”。

也可以选择「什么时候发生」「影响谁」「产生什么效果」，填写可选的数值和时长，点击「把这张卡片加入说明」。卡片会组成一条中文说明并随工程保存。卡片记录设计意图，不会自动实现游戏中的伤害、命中、范围、条件或特殊机制。

没有玩法参考包也能保存这份方案。已有参考角色定义时，可选择参考玩法并继续编辑实际词条；作者方案和真实游戏条目分别保留。

已有真实玩法参考后，点击「查看可接入的卡片」。目前能接入部分能力和队长效果，例如战斗开始、自己施放技能或强化弹射时，提高攻击或伤害，以及按目标最大生命值比例治疗。填写百分比和秒数；持续增益还要明确选择单层规则。工具会说明实际目标、时长和重复触发方式，勾选后才加入真实条目。同属性队友不含自己；主位限定只适用于能力。

「单层」只限制这张卡片的效果，重复触发采用较长的剩余时间，其他来源的效果仍可能共存。主动技能动作、直接伤害、特殊机制、未确定的单位和叠加规则继续保留为待协助。自由说明和协助申请也会一起交接，不会因接入了部分卡片而消失。

接入后可以「撤回最近一次卡片接入」，恢复原有条目并保留中文方案。如果接入后又编辑了真实条目，工具会阻止自动撤回，以免覆盖后续工作。生成和导出成功仍需接入方核验最终资源与游戏内效果。

能力和队长卡片可以附加最多两个“同时满足”的条件：自身游戏判定生命比例、当前连击数或自身已有屏障。生命比例填写百分比，连击填写整数；生命比例沿用游戏已有的判定修正。条件在发动时检查，之后变化不会自动撤销已经给出的效果。“自己已有屏障”只检查状态，不会创建屏障。

“增加连击数”选择“本次战斗连击”作为目标，填写 1–9999 的整数，没有持续时间。更多条件、任一满足、持续监听、特殊伤害或技能再次施放，可以在“复杂玩法”中继续说明和申请协助。

复杂主动技能、召唤物、技能复用等有对应的中文问题。召唤物可说明外观、数量、寿命、移动和攻击、退场及声音时点；已经有的角色动作、技能和声音可以写成复用参考。填写这些特别要求后，卡片会保留为待协助，工具不会只生成普通增益而遗漏特别要求。

## 3. 用已有素材，或上传原稿

在「作者填写包」找到对应图片或声音用途：

- 已在工程里的图片：点击「选择已有图片」，按缩略图和文件名查找、勾选并确认。
- 已在工程里的声音：按文件名选择，试听后确认对应用途。
- 新文件：使用上传按钮，工坊接收后会关联到所选用途，不需要手填素材编号。
- 整包原稿：在角色设定页接收原稿 ZIP。原始文件保留；收到原稿不等于已经完成角色用途绑定，继续按用途选择可用素材。

像素动作可导入多张逐帧 PNG，或通过网格切分导入精灵图；立绘可拖动裁剪；特效和声音可放入时间轴预览。尺寸、格式和帧数限制见[素材准备](USER_GUIDE.md#美术素材如何准备)。

上传或点选文件表示素材已关联，仍需检查尺寸、构图和实际用途。不能用“已提供”状态代替真实文件；文件不存在或关联失效时，检查会继续提示。

## 4. 缺项写清楚就能交接

进入「缺项怎样处理」，即「作者填写包」。角色核心文字、玩法、图片、动作和声音都可以记录处理方式：

| 选择 | 应写什么 | 交接含义 |
| --- | --- | --- |
| 直接填写或提供文件 | 当前文字或真实素材 | 内容已填写或文件已关联，游戏接入仍待核 |
| 请协助制作 | 具体想法、不能完成的部分、希望获得的协助及可用参考 | 作者意图已说明，制作仍待完成 |
| 暂时无法提供 | 缺少什么、具体原因、可能的替代或后续计划 | 缺项有说明，文件仍未收到 |
| 明确复用 / 由母版派生 | 参考名称和理由，以及希望沿用或派生的用途 | 复用方案已说明，来源及接入待核 |
| 不适用并说明理由 | 为什么本角色不需要此项 | 意图已说明，由制作方确认适用范围 |
| 稍后补充 | 后续计划 | 仍是作者待补，允许保存草稿 |

例如：“暂时无法提供进化立绘；目前只有基础形态母版。希望先沿用基础构图，进化版改成蓝色披风，请协助制作。”只选状态、填“待定”或留空不构成详细说明。

暂时无法确定名称或技能说明，也可记录协助理由后保存交接。详细说明会保留在交接文字、表单和内部记录中，不会把缺少的文件或尚未实现的玩法改成已完成。

整体「角色配音」可选择「无配音」并填写理由。这个声明处理未提供的角色语音；技能和战斗音效仍逐项提供、复用或说明协助。已有录音和原台词不会被无配音声明删除。

## 5. 可选：试听声音和调整音量

在「声音与台词」按中文用途整理录音、台词和音效。语音播放位置可中文选择；还不确定时交给制作方核验。

导入、试听和交接不需要先完成音量测量。测量与候选生成是可选操作，依赖本机可用的 FFmpeg / FFprobe；冻结桌面程序不自带它们。缺少工具时保留为待核或申请协助，不影响按已有内容交接。

具备条件时，在「音量与试听候选」测量原声，用表单保存目标音量和峰值上限，按名称选择参考音频；无需编辑 JSON。参考用于比较，工坊不会自行采用其他角色的音量标准。目标不确定时可保留原声并详细申请协助。

生成音量候选前，需要目标和本机可用的音频处理工具。生成后分别试听原声与候选，再主动决定是否应用。原声保留，候选不会自动替换；应用后可以撤销。音量读数和编码回读不能替代听感、游戏触发及游戏内播放验收。

获取角色台词可以保存近似排版候选，逐条检查换行与字词变化；完整原文继续保留，游戏字体和气泡显示仍待核。

## 6. 检查、保存并交接

点击「保存并下载制作交接」会先保存当前填写，再下载交接记录。再导出完整 `.wfchar.zip`，把图片、声音、原稿和可编辑工程一起交给制作方。交接记录中的内部 JSON 用于接入和追溯，作者不需要手写或修改。

「保存并交接」中的检查会区分作者待补、已说明的意图、真实素材关联和制作方待核。按提示回到对应页面处理；需要制作方协助的事项应保留理由和参考。

旧工程的技术条目未完成时，可以保留草稿、保存并导出工程。严格编译仍会阻止不有效的实际条目；草稿交接不会自动修复、删除旧技术行或放行编译。损坏文件、无效关联或不安全的数据仍可能阻止保存，应按具体提示处理。

无损图集整理默认关闭，旧工程保留原排布。先点击「查看无损整理效果」比较结果，选择「后续资源整理使用此功能」后，后续编译才在支持范围内自动应用；结果列出前后尺寸和保留原方案的理由。可用「恢复原有排布」关闭。

点击「检查用到的素材」会自动追踪已有素材引用，列出缺失、动态或不支持的依赖。作者无需填写整理配置或依赖 JSON。只有参考资料的报告会说明未覆盖当前编辑产物。编译与追踪都不表示游戏内角色已验收。

检查会继续追踪能确认的特殊能力、召唤物自身动作与支持技能、嵌套调用和公共资源。未提供的表定义、动态分支和未知条件会继续列为待核。通用图标、命中特效等通常可复用，技术文件与游戏表由制作方补齐，作者不必逐项重画或编写程序。

作者只需说明角色实际需要表现的效果；角色用到的共用特效和状态图标可以复用，不用填写游戏技术开关。详细游戏公共条件的素材收集并集保留在制作方技术报告，不作为作者制作清单。制作方继续核对实际阵容、配置和动态选择；候选齐全不表示一场战斗会全部加载，也不代表完整游戏依赖或游戏内角色已验收。

稿主在角色工坊中制作 MOD 角色的图片、像素动作、技能、能力、召唤物和声音。暂停、奖励、继续游戏、商店及交易说明等公共界面依赖只留在制作方技术报告中，继续核对固定图片、子资源和游戏运行时填入的文字、奖励图标及货币内容。它们不属于稿主制作缺项，不要求稿主选择沿用文字、补图或加入协助清单。读取布局及底层依赖检查不等于完整游戏依赖齐全或游戏内角色已验收。

“已保存的能力效果”会说明已解析与待核的效果分支。有些效果只改变数值，不需要额外图片；有些会引用特效。这个检查保留原有能力和技能脚本，额外能力、装备附加与实际触发仍需单独验证。看不懂的待核项可以直接加入协助清单。

素材检查和玩法预览都提供“可直接保存的协助清单”。逐项查看作者可以说明什么、制作方继续核对什么，再点击“把这一项加入交接说明”。它追加到现有填写包，原手写说明和素材保留；协助说明会随完整工程和制作交接导出。保存请求不会把技术缺项或游戏验收变成已完成。

| 交接状态 | 制作方应接续的工作 |
| --- | --- |
| 已提供 | 核对文件、用途、尺寸、原文和关联，继续编码及接入 |
| 仅作者意图已说明 | 根据卡片、说明、理由和参考制作资源或实现玩法 |
| 待核 / 编译阻碍 | 处理实际条目、资源接入、游戏触发与平台差异，完成真实游戏验收 |

## 保留原稿、撤销和升级

修改自动保存，也可按 Ctrl+S；撤销和重做使用 Ctrl+Z / Ctrl+Y。保存失败会显示原因，应先处理提示再确认导出结果。旧设定页与填写包内容有差异时，逐项选择采用哪一版；打开工程不会自动覆盖不同值。

原稿、参考源和原声保留。完整工程备份用于转交；保存历史和全部工程素材应另随完整 `projects/` 目录备份，自动历史不能替代异盘备份。

升级桌面版时，先在旧版保存并退出，将新版完整解压到新目录，通过「工程与升级」选择旧目录迁入。旧目录保留，编号冲突另建副本；恢复历史也会另建副本。官方模板库继续独立使用。具体迁移、恢复及旧版本说明见[常见问题](USER_GUIDE.md#常见问题)。
