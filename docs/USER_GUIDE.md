# 星点角色工坊使用说明

适用于 v0.8.0 预览版及后续源码改进。界面左上角显示当前版本，点击版本号可再次打开说明和来源信息。「尺寸与场地定位」及紧凑声明入口已包含在 v0.8.0 Windows 成品中；旧版本可能没有，请以实际界面为准。

本工具基于 [原 MOD 修改器](https://github.com/kuronzzhan-droid/startpoint-cn-mod-tools) 开发，源码采用 GPLv3；详见 [来源声明](../NOTICE.md)。工具和官方资源包分别交付。

## 第一次使用

1. 完整解压工具 ZIP 到可写目录，保留 EXE 旁的 `_internal/`。
2. 需要官方模板时，下载 [资源 1/2](https://github.com/Ku1o/StarPoint-Character-Studio/releases/download/v0.7.1/StarPoint-CN-Character-Resources-1.4.54-r3-1of2.zip) 和 [资源 2/2](https://github.com/Ku1o/StarPoint-Character-Studio/releases/download/v0.7.1/StarPoint-CN-Character-Resources-1.4.54-r3-2of2.zip)，把两份普通 ZIP 的内容都解压到工具目录，让 `templates/` 和 `definitions/` 位于 EXE 旁。无需合并压缩文件。没有资源包也可从原创角色开始。
3. 双击 `星点角色工坊.exe`。选择「原创角色」或「基于角色模板」，填写工程名。
4. 沿左侧步骤制作：角色设定 → 作者填写包 → 立绘与界面 → 像素动作 → 技能制作 → 声音与台词 → 技能与能力 → 检查与交付。
5. 修改自动保存。导出 `.wfchar.zip` 留作备份或交给其他制作人员；关闭窗口前会再次保存。

### 不懂代码，从哪里开始？

你负责画稿、声音和创意说明，不需要填写代码或分配游戏编号。先做一个能看清的最小示例，再逐步补齐，不必一次填满所有动作槽位。

1. **先写意图**：在「作者填写包」用自己的话说清角色做什么、技能对谁生效、画面和声音何时出现。不确定的数值与实现细节写“待制作方确认”，不要把设计意图当成已实现。
2. **先做一个动作**：在「像素动作」选待机等明确用途，点「导入动作图片」，核对目标动作后导入。若改的是模板图层，按下文“模板原生素材与逐帧素材”处理，不要先拆成整套逐帧图。
3. **看清再调整**：用「场地比例」比较显示大小，用「素材放大」看像素细节，再检查脚下位置、顺序和停留时间。只有确实要改变角色的游戏显示比例，才用「统一整组角色的显示倍率」；不要只改单个动作。
4. **先交草稿也可以**：到「检查与交付」补来源、用途和未完成项，按问题提示处理。导出 `.wfchar.zip` 交给制作方，并说明哪些仍需确认；导出工程不是发布到游戏。

## 安装、打开与退出

分发版解压后双击 `星点角色工坊.exe`，工作台会显示在独立桌面窗口与 Windows 任务栏中。再次双击会唤回当前窗口，不会另启一套服务。工程保存在同目录的 `projects/`。通过“导出工程”备份或发给其他人，通过“打开工程 / 参考包”继续制作。

请先完整解压到可写目录，再运行程序。交给别人时发送整个 ZIP；`_internal/` 是程序运行文件，不能只复制 EXE。点击窗口右上角 **×** 或工具的电源按钮，会先保存最后一次输入，成功后关闭整个程序。保存失败会保留窗口并显示原因；导入或编译期间请等待操作结束后再关闭。

桌面窗口使用系统 Microsoft Edge WebView2 Runtime 和 .NET Framework 4.6.2+；Windows 11 通常已提供，使用前请确保组件已安装。组件准备好后，工具、素材库和工程均可离线使用，无需安装 Python 或原 MOD 修改器。

参考包由制作方使用原 MOD 工具的角色参考导出功能准备，压缩包保留 `reference/` 目录；工坊会显示参考角色和资源版本。美术只需选择这个包。制作原创角色可以直接使用透明 PNG；连续选中多张 PNG 可一次导入一个动作。

## 工具与素材库分别交付

程序 ZIP 不含官方角色图片、音频或他人的创作工程，单独解压即可制作原创角色。配套资源在 GitHub 分为 `1of2.zip`、`2of2.zip` 两卷，必须都下载并解压到同一工具目录；不要给每卷额外套一层文件夹。将两卷合在一起的 `templates/` 和 `definitions/` 两个文件夹一起放到 EXE 旁边，点击“基于角色模板”即可搜索、筛选和新建工程。新工程会复制所选模板，后续编辑不会改动模板库。

配套库以本地已核验的**国服官方 1.4.54 基线角色表**为范围，收录 505 个角色及协力/特殊条目，含基础/进化立绘、已取得的普通/特殊像素动作、技能特效、角色语音、已解析到的技能音效，以及真实角色定义。没有混入本地追加的 26 个 MOD 角色，也不代表其他地区或其他版本的全部角色。

每个模板分别列出收录数量、资源来源、缺项和预览限制。原始资源基线未提供、特殊条目没有普通动作、无效原始时间轴以及不支持的复杂渲染都保留提示。505 个条目可建立工程，不等于每个角色的全部素材和游戏行为均已复现。

工具可在没有模板库时运行，已有工程也不依赖模板库继续存在。开发与构建方法见仓库中的 `GITHUB.md`。

## 作者填写包与制作交接

「作者填写包」是给稿主的文字和清单页面。先填角色名、称号、属性、职责、种族、进化前后形态、成长/培养消耗和队长/队员定位，再用自然语言写主动技能、PF、队长技和能力 1–6：触发条件、目标、范围、段数/倍率、持续时间、冷却、状态和图标要求。不需要填写 ActionDSL、乘区、图集坐标或服务端代码；这些字段收在每项的“制作方核验”折叠区。

同一页还提供进化前/后立绘、详情/缩略图、像素待机/移动/攻击帧、技能和 PF 帧集、图标、图集预算以及语音清单。资源和语音状态可选作者待提供、已提供、复用官方、待核验或不适用；工具不会把缺少的文件显示成完成。主城语音按进化前后成对检查，技能音频需要记录最终游戏编码/封装，普通 MP3 仅能作为源素材或预览输入。

制作状态按“作者填写包 → 制作方核验 → 资源制作 → 数据 / DSL 实现 → 本地练习战验收 → 发布整合”推进。你先提供设计、素材和待确认项；代码、游戏资源绑定和发布由制作方处理。技能预览只能检查离线画面与声音，不能替代真实游戏中的练习战。接入和验收的技术检查由制作方按生产流程记录。

“导出制作交接 JSON”只导出文字、状态、核验备注和检查结果，不包含二进制素材。完整 `.wfchar.zip` 仍用于跨工具迁移，旧项目缺少 `productionBrief` 时会补版本并把已有角色设定、技能名称/说明和旧能力文字带入填写页；原有 `gameplay`、原生词条、动作、特效、声音和扩展字段不会被替换。详细阶段说明见 [新角色生产流程](PRODUCTION-WORKFLOW.md)。

## 美术素材如何准备

| 素材 | 可导入格式 | 尺寸与制作方式 |
| --- | --- | --- |
| 像素动作 | 普通静态 PNG，建议 RGBA 透明背景 | 优先沿用模板当前画稿的实际尺寸。原创可从 32×32 或 64×64 开始；不是强制规格。每张图一个姿势。 |
| 序列特效 | 普通静态 PNG，可保留半透明边缘 | 没有统一官方宽高。原创可从 128×128 或 256×256 开始，按表现范围调整；替换模板图层优先沿用该层尺寸。 |
| 立绘 | PNG | 保留足够清晰的母版，通过用途预设生成不同裁切；基础/进化可分别提供。 |
| 角色语音、技能音效 | WAV、MP3、OGG | 用标准可播放音频；CBR MP3 可以编译为游戏存储格式。WAV/OGG 当前用于预览和交接，编译报告会列出待转换项。 |

单文件上限 64 MiB。像素画稿宽高各不超过 1022；序列特效画稿宽高各不超过 2046。旋转和缩放后也需满足编译尺寸限制。像素图集上限 1024×4096，序列特效图集上限 2048×4096，整组大图可能超出图集容量；模板骨架另保留其原生结构约束。

一组动作按 `attack_001.png`、`attack_002.png` 排序导入，可以重排、复用画稿和分别调整停留时间。例如三张图停留 6、12、6 帧，形成 24 帧（0.4 秒）动画。不必为了延长停留复制相同 PNG。单动作最多 4096 播放帧，时间基准 60 帧/秒；部分模板走路动作会注明游戏内半速。

同一动作建议保持画布和定位点一致；自动裁掉不同透明边缘会影响位置。不要把小人预先放大六倍。整张精灵图请在“导入动作图片”启用网格切分，可调整格宽/高、留白、间隔、行列顺序和透明格，直接预览切分后的动画。PSD、GIF、APNG、视频应先导出逐帧 PNG。一次最多 256 个文件、512 张画稿、128 MiB；拆分后的单帧仍须符合像素尺寸限制。

### 原图尺寸、游戏显示倍率、观看放大：改哪一个？

内置场地比例使用主线 1-2-1「追蘑菇1」第 2 区域（zone 1）的地图边界：**1080×1920 世界单位 = 180×320 美术单位**。这是一个有地图数据依据的参考关卡，不是手机分辨率，也不是所有关卡的统一尺寸。场地左上在预览中归为 (0,0)，角色与目标参考点由工具人工摆放，不是官方出生点。不同战斗场地可在“场地设置”中调整，修改尺寸后会标记为自定义。详见 [场地预览与坐标说明](SPATIAL-PREVIEW.md)。

| 名称 | 它是什么 | 什么时候调整 |
| --- | --- | --- |
| 原图尺寸 | PNG 文件宽×高，包含透明留白；不是人物本体的宽高 | 绘制或导出素材时决定。替换模板先参照当前原图，不要按预览窗口大小重画。 |
| 游戏显示倍率 | 动作的显示比例，随工程保存；不会把源 PNG 改成更大的文件 | 想改变角色大小时用「统一整组角色的显示倍率」，并交给制作方核对实际表现。 |
| 观看放大 | 预览工具栏的「观看放大」（旧版可能写「相对完整画面」），只放大工作台视图，不改变导出 | 小人看不清时使用。先选场地比例或素材放大，再按需放大；它不修改原图和定位数据。 |

例如：32×32 PNG，游戏显示倍率 6、单张「画稿缩放」为 1，动作画布按 192×192 的比例参与显示；源文件仍为 32×32。透明留白也计入画布，因此不能据此断定人物本体有多高。数字 6 只是此例，不是所有角色必须使用的规格。

「场地比例」按同一参考场地比较显示比例；「素材放大」把整段动画适配到窗口方便看细节。两种视图的观看 1× 都不保证一个源像素正好占一个屏幕像素。单张「画稿缩放」也会改变片段的变换，不能代替观看放大。仅凭窗口里看起来大小相同，无法证明两个动作的游戏显示比例相同；场地定位预览也不能代替真实游戏校准，不应把参考线或窗口边界当作已核实的游戏场地尺寸。

### 调整角色大小：统一整组动作，不逐个改

角色的一整组像素动作需要共用同一个游戏显示倍率。确认要改变角色大小后，在像素动作页选一张已有画稿，点「统一整组角色的显示倍率」，输入倍率，再点「应用到整组动作」。弹窗会一次更新全部像素动作，包括空槽位；误改可以撤销。

这会改变导出后的角色显示比例，**不是观看放大**。不会改源 PNG、单张「画稿缩放」、偏移或技能特效；已有逐帧变换仍需检查。调整后播放待机、移动和其他已制作动作，用同一场地比例复查，再做编译回读和游戏验收。模板当前倍率可作起点，不必为了看清像素修改它，也不要给不同动作分别设置不同倍率。

### 场地比例与素材放大：先比较大小，再看细节

像素动作、特效和技能预览都有「尺寸与场地定位」：

- **场地比例**：用固定参考场地看角色与特效的相对大小。比较两份素材时，保持同一场地设置与观看倍率，不要用自动适配后的画面大小判断谁更大。
- **素材放大**：把整段素材适配到预览窗口，便于检查像素、帧序和细节。它适合看清，不适合单凭屏幕大小比较角色的游戏比例。
- **尺寸读数**：原图宽高包含透明留白；可见像素范围只看非透明部分。显示范围再计入动作倍率、画稿或轨道变换；场宽／场高占比是相对当前参考场地的大小，**不是伤害、碰撞或命中范围**。模板原生素材的读数受组合结构限制，按页面提示核对，不套用单张逐帧图的规则。
- **场地设置**：可设置自定义宽高、角色参考点和目标参考点，再点「保存到工程」。这些是制作参考，随工程保存，不是游戏实测结果。更换参考点不会替你重写画稿偏移或技能轨道；默认参考的证据与适用范围以页面说明为准，这里不提供未经核实的“真实场地尺寸”。

先在场地比例中判断相对大小与位置，再切素材放大检查细节，最后回到场地比例复查。两个模式都不是战斗模拟，不含自动目标绑定、碰撞或镜头运行。

### 导出定位参考 PNG：交代位置，不当实战证据

在「尺寸与场地定位」点「导出定位参考图」，可把当前画面导出为定位参考 PNG，附当前视图模式、参考场地和帧信息。用于交接相对大小与摆放意图时，先切到「场地比例」；如果导出「素材放大」画面，应保留其“非游戏显示尺寸”说明。

图片会注明**“非实战截图”**，不能证明命中、伤害、目标跟随、镜头或真实战斗表现，也不能冒充未经实测的游戏场地证据。它不是透明源素材，不应导回动作或特效。交付时仍发送可编辑 `.wfchar.zip`，参考 PNG 只作说明补充，不能代替工程、编译回读或游戏验收。

### 模板原生素材与逐帧素材：别混用

- **逐帧素材**：时间轴是“一张画稿、一段停留时间”。每张 PNG 是完整姿势或特效阶段；导入后可以重排、复用和改停留时间。整张精灵图需要先在导入窗口切分，不要把游戏打包图集当作一张姿势。
- **模板原生素材（界面可能写“骨架动画”）**：由多个图层按模板已有的方式组合；一层不是一帧，也不是整段动画的画布。先导出该层原图，沿用尺寸与透明留白修改，再换回对应图层或通道。特效旧工程若显示「载入可编辑通道」，先点击它，再选通道用「导入 PNG 替换」。
- 想改成整张逐帧制作时，另建序列动作或「新建特效」，不要把整帧 PNG 随意替换成某一层，也不要假设工具会自动把两种结构互相转换。换图后播放整段，检查模板提示和「编译后预览」。

模板的完整定位画布与裁出的小人图块不是同一种尺寸；以当前图片或图层实际显示的宽高为准，不用猜统一尺寸。

### 脚下与锚点：让画面放得稳

“锚点”可以理解为摆放图片的固定参照点，不需要在 PNG 上画一个点。逐帧图片添加时，默认把**画布底边中点**放在预览参考位置；若底部有透明留白，人物脚底会在它上方。模板原生素材则保留模板自身的定位，不能一律按底边中点处理。

同一动作尽量让脚底在各帧画布中的相对位置一致。先播放待机或走路，看是否无意中上下跳动，再逐帧检查；不要自动裁掉每帧不同的透明边。需要调整时，选时间轴中的画稿修改「X 偏移」「Y 偏移」：X 正数向右，Y 正数向下。跳跃、浮空和身体起伏属于设计变化，不必强行把每帧脚底拉到一条线上。

逐帧画稿可以直接拖动画稿或定位十字；点击画布后用方向键微调，按住 Shift 可加大步长。选「点选脚底 / 中心」后，在当前画稿内点你希望放在定位点的位置；「可见底边对齐」「可见中心对齐」按非透明区域对齐，**只改当前画稿、不裁切源图**。底边可能是影子、武器或附属物，不一定是真正脚底；不要未经检查就把整组动作统一对齐。模板原生素材继续按图层／通道处理，不自动套用逐帧规则。

在「技能制作 → 技能预览」选中动作或特效项，可用「放在角色点」「放在目标点」「放在场中央」快速摆放，也可拖动和微调。它们只记录预览位置；“放在目标点”不是锁定或自动跟随敌人。

特效没有脚时也要写清参照位置，例如“从角色脚下出现”“贴着目标”或“留在固定地点”。工坊中摆好了位置，不等于已实现跟随、碰撞或命中范围；交给制作方在实际游戏中确认。

### 检查到哪一步，能证明什么？

1. **动作／特效编辑预览**：检查选图、顺序、位置、透明度和节奏，不验证战斗。
2. **技能制作 → 技能预览**：检查动作、多个特效、喊声和音效的配合；出现一个爆炸画面或命中音效，不表示真的击中了敌人。编排是预览与交接数据。
3. **编译后预览**：检查实际生成后重新读回的图片、时间轴和支持的音频；通过不等于角色已上线，也不等于战斗行为已验收。
4. **制作方接入真实游戏**：确认移动、目标、命中、伤害、范围、镜头、条件分支和不同场景的比例／遮挡。稿主交接时注明未验证项，不需要用代码证明它们。

## 稿主交付自检

v0.8.0 已包含这组改造；已有工程可以继续打开、保存。新说明未填写时显示「未标注」，不会当成作者已经确认。

### 1. 导入时分开纯本体与合成帧

像素动作导入会把 `_sp`、`_summon`、`_fx`、`_eff`、`_glow` 等后缀标为**疑似合成帧**，提示同名组合、目标动作和实际导入数量。用筛选只选择需要的一套；来源不清楚的图片先留在收件箱，不要为了填满槽位直接全部导入。

待机、移动、胜利、倒下、灵魂和复活通常使用纯本体帧。若设计上确实要常驻附属物，在动作说明选择「包含」，并写清出现时机。技能准备和获取登场/定格也需要说明「带 / 不带」，工坊不会因为同目录存在 `_sp` 就替你增加召唤物，也不会未经确认把合成帧换成纯本体。

文件名只是线索，工具不能识别图中一定有没有召唤物。请核对预览画面；没有后缀不等于已经过人工验收。

### 2. 在素材说明中补用途，不需要编辑 JSON

像素动作和特效页优先显示画稿预览。「来源与用途说明」默认是紧凑摘要，点击「展开编辑」查看字段；右侧也保留折叠入口。折叠只收起显示，不清空输入。补齐后仍要到检查页重新检查，摘要中的“已填写”不等于通过验收。

打开「检查与交付」中的素材说明，按实际已使用的资源填写：

- **动作**：用途、是否包含附属物、出现时机。自定义动作要说明用途；帧序、停留和循环继续在像素动作页调整。
- **特效**：复用 / 重皮 / 原创，并注明原角色、模板配色或原创范围；没有特效素材时也需在制作需求中写清计划。
- **语音**：逐条选择加入/战斗/主页等入口，填写用途和完整台词，并说明是否复用。语音和技能音效不是同一类资源。
- **UI**：基础、进化分别说明是否允许裁剪、采用什么遮罩和取景重点；重点关注头像、编队主位、技能切入、技能指引及技能连锁。禁止裁剪时应选用专用图片，不能同时保留裁剪来源。
- **整体备注**：写清哪些内容复用、哪些新画，以及授权或未完成部分。不要复制整套未改动资源冒充新稿。

### 3. 区分草稿交接与候选编译

检查页显示适用声明完成数，并分开「需先修正」「来源与用途待补」「素材与制作接入检查」。点击问题可转到对应说明或编辑位置，按「问题 / 位置 / 怎么改」处理。修改后点击「重新检查」获取当前状态。

**草稿可随时保存和导出**：`.wfchar.zip` 保留工程、源素材、`declarations.json`、`检查报告.json` 与自动生成的 `README-稿主必读.md`。接收者能看到当前仍缺哪些说明，草稿不会因此被标记为已验收。

**编译候选有安全边界**：基础状态合成帧未确认附属物与出现时机、声明不包含却选择合成帧、UI 裁剪与声明冲突等问题必须先处理。其他待补项会随候选报告交接，不代表素材已完稿。候选仍需制作方完成角色主表、平台纹理、客户端绑定和真实游戏验收。

导出的 `declarations.json` 将实际语音的入口、用途和台词写入下游读取的 `voiceDeclarations`；原工程中的作者登记不变，重复或无法对应的记录仍保留为待核对证据。未标注的 UI 遮罩在导出声明中省略 `mask`，不自动改成无裁剪或无遮罩；工程与必读说明仍显示「未标注」。

说明文档与检查只能降低交付错误，不能自动证明画面构图、音频授权、整套资源闭包或游戏实际表现完全合格。

## 立绘、单图修改与图集

官方模板的每个界面用途直接使用对应 PNG，保留实际宽高、透明度和构图。大立绘文件名中的 1440×1920 是设计命名，实际素材可能裁过透明边；工具不会把原图再次拉伸。旧工程会从保存的参考图片恢复用途对应关系，已手动编辑的旧裁剪仍然保留。

在「立绘与界面」选择基础/进化及用途：

1. 直接沿用官方原图，或「导入单张替换图片」。小图沿用当前实际宽高，大立绘可保留自己的尺寸。
2. 选择「从本形态大立绘裁剪」或「从素材裁剪」，拖动选区、拖右下角调整大小，或输入母版像素坐标与选区宽高。宽高按输出比例联动；滚轮调整选区大小。
3. 输出默认保留源透明度，也可加通用圆角。通用圆角并非游戏原生蒙版；复杂边缘可以外部绘制后导回。
4. 「导出当前用途 PNG」输出预览中同一渲染器生成的图片；「导出源图片」保留未经裁剪的素材。替换只影响当前用途，官方参考源保留，可随时恢复。

「素材浏览与单图导出」可按类别、名称和尺寸搜索，逐张下载官方 UI、像素画稿和特效贴图。像素片段与特效通道旁也有直接导出源图的入口。导出 PNG 不包含预览背景或观看缩放，保留原尺寸与透明度；外部修改后导回原用途、片段或通道即可。

像素动作和技能特效编译时自动拼图并生成配套坐标/时间轴；「查看实际图集」读取真实编译产物，可以点击任何图块单独导出。UI 小图也自动拼成交接图集，附 PNG 和 JSON 坐标，并逐张回读检查。这张 UI 交接图集不等同于客户端的 illustration 图集，不能直接改名覆盖游戏；大立绘、技能切入保持独立文件。

创作者可交出可编辑工程与离线编译产物，不需要手工拼图。接收制作方仍负责游戏 UI 专用图集与定位表、Android/iOS 切入纹理、角色数据和实际游戏验收。编译报告始终分别标记这些接入项。

## 特效通道与能力组件

官方原生特效现在按实际图层实例生成独立通道。同一张图片多次出现，可以各自换图、隐藏、调整位置、旋转、缩放、不透明度和出现区间；开始/结束帧改变时会拉伸源动画。每个通道可设置关键帧，帧间自动线性过渡，也可复制、调整层序或从透明 PNG 新增通道。缩略图、名称搜索、来源图片筛选和“只看所选通道”帮助定位复杂特效。

旧工程打开“技能制作 → 特效编辑”，点击“载入可编辑通道”即可升级所选特效。原先的换图和偏移设置、原始文件、音效事件保留。通道未编辑时沿用原生编译；编辑后把最终合成结果编码成 PartsAnimation 与图集，再从实际产物回读预览。单张替换图仍限 2046 px，总时长 4096 帧；常规通道上限 2048 条，超大官方特效保留全部原有通道并允许额外添加 256 条；编译图集上限 2048×8192，超限会报明原因。

“技能与能力”里的“自由组合”新建一条真实效果，“拆解与组合”编辑已有条目。前置条件（最多 3 个）、触发、效果、作用对象和数值分别调整；可搜索完整枚举库，按百分比、次数/倍率、秒或原始值填写。每块支持复制/粘贴、重置、从官方或 MOD 词条库仅取这一块；词条库也可只追加所勾选的效果行。多条效果可在六个槽位间复制/移动。中文说明、编号与数值检查实时更新，保存后支持撤销、重做和导出重开。

继续使用已有 `1.4.54-r3` 完整角色资源包，无需重新下载。MOD 内工坊和独立创作版共用上述功能。本版只改制作工具和工程，不分配游戏 ID，不改玩家存档或现役角色数据。

## 演出、语音和技能音效

“技能制作”包含“特效编辑”和“技能预览”两个页签，共用特效和声音事件。前者调整单个特效；后者查看动作、多个特效和声音的配合。例如第 0 帧小人起手、第 6 帧喊声与特效出现、第 12 帧播放命中音效。每项可选择素材、设置开始/结束帧；位置、倍率与层级放在展开设置中。伤害、目标选择、镜头和剧情事件仍需游戏接入。

“声音与台词”分别管理角色说话和技能/战斗音效。角色语音可用于主界面、加入、进化、战斗开始、技能喊声、技能就绪、强化弹射、攻击、落穴、胜利、登录及剧情短语。台词优先带入已登记原文；没有登记的文本不会自动猜测。自填文字用于设计和交接，不会自动变成游戏字幕。

技能音效是挥砍、蓄力、雷鸣、爆炸、命中等招式声音。在特效的“声音事件”中绑定音频、调整开始帧、结束帧、循环次数及音量，也可以添加角色喊声。预览先完成图片与声音解码，再用同一音频时钟调度；编译后预览读取实际生成并解码的 MP3 和声音时间轴。模板中的循环音效和指定结束帧会保留并参与预览、编译；游戏时间轴音量使用 0–10 整数，编译时从编辑器 0–1 音量按 0.1 步长量化。暂停或切换页面会停止播放。单段结束时声音一并停止；需检查完整余音时，可在技能组合预览页延长总时长。

常用流程：角色设定 → 基础/进化立绘 → 按用途调整头像与切入裁切 → 像素动作 → 技能制作（特效编辑 → 组合预览） → 检查与交付。修改会自动保存，也可按 Ctrl+S；撤销/重做使用 Ctrl+Z / Ctrl+Y。

## MOD 内制作与创作者交付

原 MOD 修改器新增“角色工坊”页签，嵌入与独立版相同的界面和服务。词条目录、数值换算和生成器已抽到共用模块；两个入口使用同一种 `.wfchar.zip` 工程。切回 MOD 其他页面前会保存，保存失败时留在工坊。独立 EXE 继续只提供角色制作界面。

完整角色资源库 `1.4.54-r3` 合并原美术声音库与角色定义，GitHub 下载为两个普通 ZIP 卷，也兼容原来的单 ZIP 完整包。定义含 505 个官方角色的真实引用、技能版本、队长技、六槽能力、成长参考、语音绑定及 489 份原有演示回放。将资源包中的 `templates/` 和 `definitions/` 一起放到 EXE 旁。在 MOD 内使用时放入 `tools/character-studio/`。仍兼容旧版小型定义 ZIP 的单独导入。已有美术工程可点击“选择参考角色定义”；安装后新建匹配官方模板会自动带入定义。只有角色和版本一致才会将素材与定义结合。创作者按“工具＋完整资源”两类下载；GitHub 的资源分为两份普通 ZIP，两份都需解压。MOD 接驳属于原项目代码更新。

“从词条库选择”可按角色名、效果或编号搜索现成能力，逐条勾选后追加到队长技或指定能力槽，并可撤销、重做、继续改数值。MOD 内直接读取当前修改器的能力库；独立版使用资源包的官方离线词条库。来源角色不被修改，专属条件与资源引用保留供接入时核对。动作列表点击、复制、撤销会保持当前滚动位置。

“技能与能力”可查看实际条目、编辑技能名称/说明/能量、调整能力数值/持续时间/主位条件、删除效果或按触发/对象/效果添加常用条目。复杂原始字段继续保留。定义包中的原始异常条目保留并提示，编辑后仍需通过校验；不会为消除提示而改写官方原值。设计备注可通过右上角切换，备注和实际条目分别编辑。

编译包新增 `native-draft/`，使用原 MOD 的表编码并回读核对技能与能力数据。临时槽位键尚未分配游戏编号，草稿表不能覆盖游戏完整主表；正式新角色生成、成长/玛纳板绑定和存档兼容验收仍待完成。

完整官方技能的战斗预览仍未实现。复用现有 MOD 功能能统一动画、特效和声音预览，但完整演示依赖客户端战斗运行场景。核实依据和后续接入结构见 `PREVIEW-RUNTIME.md`，不能把素材播放或已收录回放文件当成完整技能还原。

## 产品约定

- 首页只有基于模板与原创两条新建路线。与新角色创作无关的卡池、商城、深渊、账号、服务器管理不进入界面。
- 图片数量、动作片段和播放帧数分别显示。时间轴可以编辑并合成播放，帧墙仅用于选材。
- 支持的素材必须有成品预览；缺少依赖或尚未支持的运行行为必须显示具体问题，不标成通过。
- 原创工程可以制作原创外观、动作与序列特效。全新游戏机制仍需接入对应客户端逻辑；工具不会根据自然语言伪造已实现的战斗能力。
- 交付分为可编辑工程、源素材交接包和离线编译产物。离线编译不是角色上线，也不代表真机验收。
- 软件只读导入文件，只写自己的工程目录；不读取连接配置、数据库、账号信息，不调用发布、同步或设备接口。

## 常见问题

- **官方模板显示待补项，是漏导出了吗？** 查看条目具体说明：原始资源缺项、工具渲染限制和特殊条目说明分别列出。不能只凭「待补」判断丢失文件。保留角色名、动作或特效名、问题提示以便反馈。
- **只能看到技能素材，不能还原战斗？** 当前可编辑通道和时序，并查看素材及编译结果；移动、目标、命中、镜头和条件分支的完整战斗运行仍待接入。
- **模板里已有的特效怎样修改？** 进入「技能制作 → 特效编辑」，选择特效；旧工程可点击「载入可编辑通道」。在通道中换图、改关键帧或调整出现区间。
- **资源包更新后旧工程为什么没变？** 工程创建时已独立复制素材；资源更新不会覆盖你的修改。要查看新版官方原样，请另建模板工程。
- **如何升级工具？** 先在旧版保存并退出，将新版完整解压到另一个目录。新版打开「工程与升级 → 选择旧版文件夹并迁入」，选择旧工具目录或其中的 `projects/`。程序会复制工程、全部素材和历史记录，逐文件校验后才放入新工程列表。旧目录保留；重复迁入会跳过已迁入的相同版本，编号冲突时另建副本。
- **官方素材库需要重下吗？** 不需要。把旧版 `templates/`、`definitions/` 完整复制到新版 EXE 旁，或安装原来的资源 ZIP。迁入工程不依赖重新下载模板；工程内已有素材和编辑不会被模板更新替换。
- **浏览器 / MOD 内怎样迁入？** 导入旧版导出的 `.wfchar.zip`，或在关闭两个工具后手动复制完整 `projects/` 到全新的空目录。文件夹迁入按钮由独立桌面窗口提供。
- **怎样恢复误改或损坏的工程？** 在「工程与升级」选中工程，从保存历史点击「恢复为副本」。程序会验证该记录需要的素材，再建立独立副本，原工程仍保留。损坏或不支持的工程会显示提示，不会从列表消失；没有历史时可导入以前导出的工程备份。若源素材已被外部删除或损坏，需要使用另外保存的完整备份。
- **保存与数据格式怎样兼容？** 兼容现有 `starpoint-character-studio-v1` 工程与工程 ZIP，保留旧裁剪、动作时长、特效通道、声音、能力及扩展字段；读取不会改写磁盘文件。后续格式变更须逐版本迁移，不支持的格式会在写入前拒绝。每次覆盖工程记录前先保存原始 JSON，再以临时文件写入并替换；备份或保存失败会停止，不覆盖原工程。素材使用独立文件，历史恢复依赖这些素材，因此请保留整个工程文件夹。
- **能退回旧版吗？** 保留升级前的旧工具与工程目录，回退时打开那一份。不要把已由未来新版转换的工程交回缺少格式检查的旧程序编辑。现有旧版本无法事后获得新保护措施。
- **哪些内容需要另存备份？** 「导出所选工程备份」保存当前工程与素材，历史记录应随完整 `projects/` 文件夹另外备份到其他位置。自动历史记录保存在同一磁盘，不能替代异盘备份。升级时不要只替换 EXE、混用 `_internal/` 或直接覆盖旧目录。
- **为什么启动时提示 `Python.Runtime.dll` 或 `WebView2.Core.dll` 未能加载？** 0.7.2 及以后 Windows 分发包自带 .NET Framework 远程程序集兼容配置，解压后不需要逐个 DLL 解除锁定。若使用 v0.7.1，请先对原始 ZIP 右键属性选择“解除锁定”，再完整解压到新目录；只解除一个 DLL 可能在下一个依赖处继续报错。
- **怎样报告问题？** 在 [Issues](https://github.com/Ku1o/StarPoint-Character-Studio/issues) 提供工具版本、Windows 版本、操作步骤、提示、角色/动作/特效名及资源包版本。重现工程可优先使用自己制作的最小示例。
