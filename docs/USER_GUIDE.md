# 星点角色工坊使用说明

适用于 v0.7.1 预览版。界面左上角显示当前版本，点击版本号可再次打开说明和来源信息。

本工具基于 [原 MOD 修改器](https://github.com/kuronzzhan-droid/startpoint-cn-mod-tools) 开发，源码采用 GPLv3；详见 [来源声明](../NOTICE.md)。工具和官方资源包分别交付。

## 第一次使用

1. 完整解压工具 ZIP 到可写目录，保留 EXE 旁的 `_internal/`。
2. 需要官方模板时，下载 [资源 1/2](https://github.com/Ku1o/StarPoint-Character-Studio/releases/download/v0.7.1/StarPoint-CN-Character-Resources-1.4.54-r3-1of2.zip) 和 [资源 2/2](https://github.com/Ku1o/StarPoint-Character-Studio/releases/download/v0.7.1/StarPoint-CN-Character-Resources-1.4.54-r3-2of2.zip)，把两份普通 ZIP 的内容都解压到工具目录，让 `templates/` 和 `definitions/` 位于 EXE 旁。无需合并压缩文件。没有资源包也可从原创角色开始。
3. 双击 `星点角色工坊.exe`。选择「原创角色」或「基于角色模板」，填写工程名。
4. 沿左侧步骤制作：角色设定 → 立绘与界面 → 像素动作 → 技能制作 → 声音与台词 → 技能与能力 → 检查与交付。
5. 修改自动保存。导出 `.wfchar.zip` 留作备份或交给其他制作人员；关闭窗口前会再次保存。

## 安装、打开与退出

分发版解压后双击 `星点角色工坊.exe`，工作台会显示在独立桌面窗口与 Windows 任务栏中。再次双击会唤回当前窗口，不会另启一套服务。工程保存在同目录的 `projects/`。通过“导出工程”备份或发给其他人，通过“打开工程 / 参考包”继续制作。

请先完整解压到可写目录，再运行程序。交给别人时发送整个 ZIP；`_internal/` 是程序运行文件，不能只复制 EXE。点击窗口右上角 **×** 或工具的电源按钮，会先保存最后一次输入，成功后关闭整个程序。保存失败会保留窗口并显示原因；导入或编译期间请等待操作结束后再关闭。

桌面窗口使用系统 Microsoft Edge WebView2 Runtime 和 .NET Framework 4.6.2+；Windows 11 通常已提供，使用前请确保组件已安装。组件准备好后，工具、素材库和工程均可离线使用，无需安装 Python 或原 MOD 修改器。

参考包由制作方使用原 MOD 工具的角色参考导出功能准备，压缩包保留 `reference/` 目录；工坊会显示参考角色和资源版本。美术只需选择这个包。制作原创角色可以直接使用透明 PNG；连续选中多张 PNG 可一次导入一个动作。

## 工具与素材库分别交付

程序 ZIP 不含官方角色图片、音频或他人的创作工程，单独解压即可制作原创角色。配套资源在 GitHub 分为 `1of2.zip`、`2of2.zip` 两卷，必须都下载并解压到同一工具目录；不要给每卷额外套一层文件夹。将两卷合在一起的 `templates/` 和 `definitions/` 两个文件夹一起放到 EXE 旁边，点击“基于角色模板”即可搜索、筛选和新建工程。新工程会复制所选模板，后续编辑不会改动模板库。

配套库以本地已核验的**国服官方 1.4.54 基线角色表**为范围，收录 505 个角色及协力/特殊条目，含基础/进化立绘、已取得的普通/特殊像素动作、技能特效、角色语音、已解析到的技能音效，以及真实角色定义。没有混入本地追加的 26 个 MOD 角色，也不代表其他地区或其他版本的全部角色。

每个模板分别列出收录数量、资源来源、缺项和预览限制。原始资源基线未提供、特殊条目没有普通动作、无效原始时间轴以及不支持的复杂渲染都保留提示。505 个条目可建立工程，不等于每个角色的全部素材和游戏行为均已复现。

工具可在没有模板库时运行，已有工程也不依赖模板库继续存在。开发与构建方法见仓库中的 `GITHUB.md`。

## 美术素材如何准备

| 素材 | 可导入格式 | 尺寸与制作方式 |
| --- | --- | --- |
| 像素动作 | 普通静态 PNG，建议 RGBA 透明背景 | 优先沿用模板当前画稿的实际尺寸。原创可从 32×32 或 64×64 开始；不是强制规格。每张图一个姿势。 |
| 序列特效 | 普通静态 PNG，可保留半透明边缘 | 没有统一官方宽高。原创可从 128×128 或 256×256 开始，按表现范围调整；替换模板图层优先沿用该层尺寸。 |
| 立绘 | PNG | 保留足够清晰的母版，通过用途预设生成不同裁切；基础/进化可分别提供。 |
| 角色语音、技能音效 | WAV、MP3、OGG | 用标准可播放音频；CBR MP3 可以编译为游戏存储格式。WAV/OGG 当前用于预览和交接，编译报告会列出待转换项。 |

单文件上限 64 MiB。像素画稿宽高各不超过 1022；序列特效画稿宽高各不超过 2046。旋转和缩放后也需满足编译尺寸限制。像素图集上限 1024×4096，序列特效图集上限 2048×4096，整组大图可能超出图集容量；模板骨架另保留其原生结构约束。

一组动作按 `attack_001.png`、`attack_002.png` 排序导入，可以重排、复用画稿和分别调整停留时间。例如三张图停留 6、12、6 帧，形成 24 帧（0.4 秒）动画。不必为了延长停留复制相同 PNG。单动作最多 4096 播放帧，时间基准 60 帧/秒；部分模板走路动作会注明游戏内半速。

同一动作建议保持画布和定位点一致；自动裁掉不同透明边缘会影响位置。不要把小人预先放大六倍。整张精灵图请在“导入动作图片”启用网格切分，可调整格宽/高、留白、间隔、行列顺序和透明格，直接预览切分后的动画。PSD、GIF、APNG、视频应先导出逐帧 PNG。一次最多 256 个文件、512 张画稿、128 MiB；拆分后的单帧仍须符合像素尺寸限制。

## 立绘、单图修改与图集

官方模板的每个界面用途直接使用对应 PNG，保留实际宽高、透明度和构图。大立绘文件名中的 1440×1920 是设计命名，实际素材可能裁过透明边；工具不会把原图再次拉伸。旧工程会从保存的参考图片恢复用途对应关系，已手动编辑的旧裁剪仍然保留。

在「立绘与界面」选择基础/进化及用途：

1. 直接沿用官方原图，或「导入单张替换图片」。小图沿用当前实际宽高，大立绘可保留自己的尺寸。
2. 选择「从本形态大立绘裁剪」或「从素材裁剪」，拖动选区、拖右下角调整大小，或输入母版像素坐标与选区宽高。宽高按输出比例联动；滚轮调整选区大小。
3. 输出默认保留源透明度，也可加通用圆角。通用圆角并非游戏原生蒙版；复杂边缘可以外部绘制后导回。
4. 「导出当前用途 PNG」输出预览中同一渲染器生成的图片；「导出源图片」保留未经裁剪的素材。替换只影响当前用途，官方参考源保留，可随时恢复。

「素材浏览与单图导出」可按类别、名称和尺寸搜索，逐张下载官方 UI、像素画稿和特效贴图。像素片段与特效通道旁也有直接导出源图的入口。导出 PNG 不包含预览背景或观看缩放，保留原尺寸与透明度；外部修改后导回原用途、片段或通道即可。

像素动作和技能特效编译时自动拼图并生成配套坐标/时间轴；「查看实际图集」读取真实编译产物，可以点击任何图块单独导出。UI 小图也自动拼成交接图集，附 PNG 和 JSON 坐标，并逐张回读检查。这张 UI 交接图集不等同于客户端的 illustration 图集，不能直接改名覆盖游戏；大立绘、技能切入保持独立文件。

创作者可交出可编辑工程与离线编译产物，不需要手工拼图。接收制作方仍负责游戏 UI 专用图集与定位表、Android/iOS 切入纹理、角色数据和实际游戏验收。编译报告始终分别标记这些接入项。

## 特效通道与能力组件

官方原生特效现在按实际图层实例生成独立通道。同一张图片多次出现，可以各自换图、隐藏、调整位置、旋转、缩放、不透明度和出现区间；开始/结束帧改变时会拉伸源动画。每个通道可设置关键帧，帧间自动线性过渡，也可复制、调整层序或从透明 PNG 新增通道。缩略图、名称搜索、来源图片筛选和“只看所选通道”帮助定位复杂特效。

旧工程打开“技能制作 → 特效编辑”，点击“载入可编辑通道”即可升级所选特效。原先的换图和偏移设置、原始文件、音效事件保留。通道未编辑时沿用原生编译；编辑后把最终合成结果编码成 PartsAnimation 与图集，再从实际产物回读预览。单张替换图仍限 2046 px，总时长 4096 帧；常规通道上限 2048 条，超大官方特效保留全部原有通道并允许额外添加 256 条；编译图集上限 2048×8192，超限会报明原因。

“技能与能力”里的“自由组合”新建一条真实效果，“拆解与组合”编辑已有条目。前置条件（最多 3 个）、触发、效果、作用对象和数值分别调整；可搜索完整枚举库，按百分比、次数/倍率、秒或原始值填写。每块支持复制/粘贴、重置、从官方或 MOD 词条库仅取这一块；词条库也可只追加所勾选的效果行。多条效果可在六个槽位间复制/移动。中文说明、编号与数值检查实时更新，保存后支持撤销、重做和导出重开。

继续使用已有 `1.4.54-r3` 完整角色资源包，无需重新下载。MOD 内工坊和独立创作版共用上述功能。本版只改制作工具和工程，不分配游戏 ID，不改玩家存档或现役角色数据。

## 演出、语音和技能音效

“技能制作”包含“特效编辑”和“技能预览”两个页签，共用特效和声音事件。前者调整单个特效；后者查看动作、多个特效和声音的配合。例如第 0 帧小人起手、第 6 帧喊声与特效出现、第 12 帧播放命中音效。每项可选择素材、设置开始/结束帧；位置、倍率与层级放在展开设置中。伤害、目标选择、镜头和剧情事件仍需游戏接入。

“声音与台词”分别管理角色说话和技能/战斗音效。角色语音可用于主界面、加入、进化、战斗开始、技能喊声、技能就绪、强化弹射、攻击、落穴、胜利、登录及剧情短语。台词优先带入已登记原文；没有登记的文本不会自动猜测。自填文字用于设计和交接，不会自动变成游戏字幕。

技能音效是挥砍、蓄力、雷鸣、爆炸、命中等招式声音。在特效的“声音事件”中绑定音频、调整开始帧、结束帧、循环次数及音量，也可以添加角色喊声。预览先完成图片与声音解码，再用同一音频时钟调度；编译后预览读取实际生成并解码的 MP3 和声音时间轴。模板中的循环音效和指定结束帧会保留并参与预览、编译；游戏时间轴音量使用 0–10 整数，编译时从编辑器 0–1 音量按 0.1 步长量化。暂停或切换页面会停止播放。单段结束时声音一并停止；需检查完整余音时，可在技能组合预览页延长总时长。

常用流程：角色设定 → 基础/进化立绘 → 按用途调整头像与切入裁切 → 像素动作 → 技能制作（特效编辑 → 组合预览） → 检查与交付。修改会自动保存，也可按 Ctrl+S；撤销/重做使用 Ctrl+Z / Ctrl+Y。

## MOD 内制作与创作者交付

原 MOD 修改器新增“角色工坊”页签，嵌入与独立版相同的界面和服务。词条目录、数值换算和生成器已抽到共用模块；两个入口使用同一种 `.wfchar.zip` 工程。切回 MOD 其他页面前会保存，保存失败时留在工坊。独立 EXE 继续只提供角色制作界面。

完整角色资源库 `1.4.54-r3` 合并原美术声音库与角色定义，GitHub 下载为两个普通 ZIP 卷，也兼容原来的单 ZIP 完整包。定义含 505 个官方角色的真实引用、技能版本、队长技、六槽能力、成长参考、语音绑定及 489 份原有演示回放。将资源包中的 `templates/` 和 `definitions/` 一起放到 EXE 旁。在 MOD 内使用时放入 `tools/character-studio/`。仍兼容旧版小型定义 ZIP 的单独导入。已有美术工程可点击“选择参考角色定义”；安装后新建匹配官方模板会自动带入定义。只有角色和版本一致才会将素材与定义结合。创作者按“工具＋完整资源”两类下载；GitHub 的资源分为两份普通 ZIP，两份都需解压。MOD 接驳属于原项目代码更新。

“从词条库选择”可按角色名、效果或编号搜索现成能力，逐条勾选后追加到队长技或指定能力槽，并可撤销、重做、继续改数值。MOD 内直接读取当前修改器的能力库；独立版使用资源包的官方离线词条库。来源角色不被修改，专属条件与资源引用保留供接入时核对。动作列表点击、复制、撤销会保持当前滚动位置。

“技能与能力”可查看实际条目、编辑技能名称/说明/能量、调整能力数值/持续时间/主位条件、删除效果或按触发/对象/效果添加常用条目。复杂原始字段继续保留。定义包中的原始异常条目保留并提示，编辑后仍需通过校验；不会为消除提示而改写官方原值。设计备注可通过右上角切换，备注和实际条目分别编辑。

编译包新增 `native-draft/`，使用原 MOD 的表编码并回读核对技能与能力数据。临时槽位键尚未分配游戏编号，草稿表不能覆盖游戏完整主表；正式新角色生成、成长/玛纳板绑定和存档兼容验收仍待完成。

完整官方技能的战斗预览仍未实现。复用现有 MOD 功能能统一动画、特效和声音预览，但完整演示依赖客户端战斗运行场景。核实依据和后续接入结构见 `PREVIEW-RUNTIME.md`，不能把素材播放或已收录回放文件当成完整技能还原。

“编译后预览”使用本次编码后重新解码的图集和时间轴；没有把编辑器帧列表直接当作回读结果。回读成功与游戏内验收是两件分别记录的事情。上述缺口属于尚未完成的功能，当前版本不声称覆盖所有游戏显示效果。

开发版：安装 Python 3.11+，执行 `python -m pip install -r requirements-desktop.txt` 后运行 `python studio.py --open`。可通过 `--templates <模板库目录>`、`--definitions <定义包目录>` 指定资源位置。`--no-open` 仅启动本机服务，供浏览器与自动验收使用。源码分发目录的 `core/` 自带八个共用模块及词条枚举/说明数据，不需要原修改器或服务端。

## 产品约定

- 首页只有基于模板与原创两条新建路线。与新角色创作无关的卡池、商城、深渊、账号、服务器管理不进入界面。
- 图片数量、动作片段和播放帧数分别显示。时间轴可以编辑并合成播放，帧墙仅用于选材。
- 支持的素材必须有成品预览；缺少依赖或尚未支持的运行行为必须显示具体问题，不标成通过。
- 原创工程可以制作原创外观、动作与序列特效。全新游戏机制仍需接入对应客户端逻辑；工具不会根据自然语言伪造已实现的战斗能力。
- 交付分为可编辑工程、源素材交接包和离线编译产物。离线编译不是角色上线，也不代表真机验收。
- 软件只读导入文件，只写自己的工程目录；不读取连接配置、数据库、账号信息，不调用发布、同步或设备接口。

## 存档影响

工坊只保存创作工程，不修改玩家进度、数据库结构或游戏角色 ID。角色正式接入时，仍须由接入工具检查 ID、角色与技能表、玛纳板、平台资源和存档导入导出兼容。

资源通过本仓库 Releases 提供，不提交到 Git 源码。每份资源 ZIP 约 1.74 GiB；只安装其中一卷会缺少部分角色素材。已经装好完整 1.4.54-r3 资源的用户不必重下。页面上的 `Source code` 是 GitHub 自动生成的源码下载，使用 Windows 工具时无需下载。发布附件不再提供单独 `.sha256` 文件，程序内部的完整性检查仍保留。

## 常见问题

- **官方模板显示待补项，是漏导出了吗？** 查看条目具体说明：原始资源缺项、工具渲染限制和特殊条目说明分别列出。不能只凭「待补」判断丢失文件。保留角色名、动作或特效名、问题提示以便反馈。
- **只能看到技能素材，不能还原战斗？** 当前可编辑通道和时序，并查看素材及编译结果；移动、目标、命中、镜头和条件分支的完整战斗运行仍待接入。
- **模板里已有的特效怎样修改？** 进入「技能制作 → 特效编辑」，选择特效；旧工程可点击「载入可编辑通道」。在通道中换图、改关键帧或调整出现区间。
- **资源包更新后旧工程为什么没变？** 工程创建时已独立复制素材；资源更新不会覆盖你的修改。要查看新版官方原样，请另建模板工程。
- **如何升级工具？** 先关闭工具并导出工程备份。新版完整解压到新目录，再复制原来的 `projects/`、`templates/` 和 `definitions/`；不要只替换 EXE 或混用 `_internal/`。
- **怎样报告问题？** 在 [Issues](https://github.com/Ku1o/StarPoint-Character-Studio/issues) 提供工具版本、Windows 版本、操作步骤、提示、角色/动作/特效名及资源包版本。重现工程可优先使用自己制作的最小示例。
