# 角色工坊交互改进提案：校验报告、提示文案与 `.wfchar` 模板字段

日期：2026-10-06　范围：**提案文档，不含代码改动**（工坊 `.py` 正由另一条聊天修改，本文件只描述“哪个工具、什么时机、显示什么文字、需要什么字段”，供其取舍）。

## 0. 背景（一句话）

凉月（159992）制作过程中暴露的问题都不是“素材不够”，而是**素材身份与适用范围没有被声明**：基础状态误用合成帧、获取演出是否带召唤物不明、UI 五类裁剪与形状遮罩未标注、特效/音效/语音来源未分类。工坊目前 37 项硬门只检查“文件在不在”，不检查“文件对不对、说明全不全”。本提案把“来源与声明”补成可校验数据。

---

## 1. 改动点 A：像素动作导入窗口（工坊 → 像素动作 → 导入动作图片）

对应实现：`tools/character-studio/web/pixel-import.js`、`tools/character-studio/pixel_import.py`。

### A1 时机：选择文件后、分配归属的预览阶段

**触发条件**：同一批文件（或目标动作现有画稿）中，存在“同名纯本体帧 + 带后缀变体帧”的组合（如 `neutral_001.png` 与 `neutral_001_sp.png`；后缀集合可配置：`_sp`、`_summon`、`_fx`、`_eff`、`_glow`）。

显示文字（黄色提示条，不阻断）：

> 检测到 104 组“纯本体帧 + 合成帧”同名素材（后缀 `_sp`）。
> 基础状态（待机/移动/胜利/倒下/灵魂/复活）请只导入**纯本体帧**；合成帧请放入素材收件箱，或导入到明确需要附属物的状态（如技能准备）。
> 如果本状态确实要带召唤物，请在动作说明中写明“本状态包含召唤物”。

附带按钮：`只看纯本体帧` / `只看合成帧` / `我知道了`。

### A2 时机：归属自动匹配失败时

现状：`pixelMatch()` 会剥掉结尾数字与 `_`/`-`，`neutral_001_sp.png` 这类名字匹配不到槽位，落入“未分类图片 / 素材收件箱”。

改进：匹配失败且文件名命中附属物后缀时，归属组名显示为：

> `未分类（疑似合成帧）`
> 这些帧带了 `_sp` 后缀，无法自动判断对应状态。请手动选择目标动作，或放入收件箱稍后处理。

### A3 时机：点击“导入到工程”前的摘要

在底部状态栏追加一行来源汇总，例如：

> 本次导入 66 张：纯本体 66 / 合成 0；目标动作 8 个。全部为纯本体帧。

或：

> 本次导入 143 张：其中 104 张带 `_sp` 后缀，将写入待机/移动等 8 个基础状态。请确认这些状态允许携带附属物，否则请取消并改选纯本体帧。

### A4 时机：导入完成提示

> 已导入 66 张画稿到 8 个动作。待机/移动等基础状态使用的是无后缀纯本体帧。

## 2. 改动点 B：像素动作卡与动作说明字段

对应实现：`tools/character-studio/action_presets.py`（槽位定义）、`studio_core.py`（工程校验）、`web/character-workflow.js`（动作卡渲染）。

每个动作增加三个可选字段（旧工程缺失 = `未标注`，不阻断打开）：

| 字段 | 类型 | 显示名 | 说明 |
| --- | --- | --- | --- |
| `animations[].purpose` | string | 用途说明 | 已有 preset 的动作用 preset 文案预填；自定义动作必须作者填写 |
| `animations[].includesCompanion` | `true` / `false` / `""` | 是否包含召唤物/附属物 | `""` 显示为“未标注” |
| `animations[].companionNote` | string | 附属物说明 | 出现时机（如“仅开大时出现两只召唤物”） |

同时给素材记录增加来源标记（导入时自动写、可手工改）：

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `assets.<id>.variant` | `plain` / `composite` / `effect` / `ui` / `unknown` | 由文件名后缀推断（无后缀=plain，命中 `_sp` 等=composite） |
| `assets.<id>.sourceNote` | string | 作者补充说明（可空） |

动作卡显示效果（示例）：

> 待机 · 2 段画稿 · 来源：纯本体　|　包含召唤物：否
> 技能准备 · 50 tick · 来源：合成帧　|　包含召唤物：是（开大时出现两只召唤物）
> 获取·登场 · 16 段画稿 · 来源：合成帧　|　包含召唤物：**未标注**（建议填写）

## 3. 改动点 C：“检查与交付”页新增检查项（`project_checks`）

对应实现：`tools/character-studio/studio_core.py` 的 `project_checks()`，以及 `web/` 检查页渲染。

新增以下 issue（保持“**问题 / 位置 / 怎么改**”三段式文案）：

| 检查 id | 级别 | 触发条件 | 文案（显示内容） |
| --- | --- | --- | --- |
| `base_state_composite_suspect` | warning | `neutral`/`walk_front`/`walk_back`/`kachidoki`/`into_coffin`/`ghost_raise`/`ghost_neutral`/`revive` 的任一 clip 指向 `variant=composite` 素材，且 `includesCompanion` 不为 `true` | 「待机/移动等基础状态有 N 段画稿疑似带附属物（`_sp` 合成帧）。若设计上确实要带，请在『像素动作 → 该动作 → 是否包含召唤物』改为“是”并写明时机；否则请替换为无后缀的纯本体帧。」 |
| `companion_undeclared` | todo | `skill_ready`、`special_land`、`special_pose` 动作的 `includesCompanion` 为 `""`，或素材中存在 composite 但字段未填 | 「『获取·登场/定格』尚未说明是否带召唤物。请在该动作的『附属物说明』中二选一填写“带/不带”，否则制作方只能按默认处理。」 |
| `animation_notes_missing` | todo | 自定义动作（非官方模板）缺 `purpose`，或动作缺帧数/停留说明 | 「动作『XXX』还没有用途说明。请在动作卡中填写：用途、帧数、每帧停留、循环方式。」 |
| `frame_group_mixed` | warning | 同一动作目录内同时存在 plain 与 composite 帧，且未做任何选择 | 「动作『XXX』同时导入了纯本体帧和合成帧（N/M）。请只保留一套，或明确说明两套各自的用途。」 |
| `effect_origin_missing` | warning | `effects[]` 中任一特效缺 `origin` | 「技能特效『XXX』未声明来源。请选择：复用（某角色）/ 重皮（模板+配色）/ 完全原创（四件套）。」 |
| `voice_usage_missing` | todo | 存在语音素材但 `voiceDeclarations` 缺入口分类或文本 | 「有 N 条语音没有登记入口分类或台词文本。请补 `语音对照表`：文件 / ally·battle·home / 用途 / 台词。」 |
| `ui_special_crop_unmarked` | info | 五类重点用途（`square`、`thumb_party_main`、`skill_cutin`、`battle_control_board`、`cutin_skill_chain`）有独立替换图，但未声明取景/遮罩意图 | 「『技能插入图』使用了单独替换图，但未说明是否禁止从母版自动裁切、是否需要形状遮罩。请补充声明。」 |

页面顶部汇总建议显示：

> 提交就绪度：素材 66/66 · 声明 8/14　（3 项待补说明不会阻止导出，但制作方开工前需要确认）

## 4. 改动点 D：`.wfchar` 工程模板与 README 需要的字段

对应实现：`tools/character-studio/project_storage.py`、`template_library.py`、`production_brief.py`，以及包内 `交接说明.txt`。

### D1 建议新增字段（全部可选，缺省表示“未标注”）

```jsonc
{
  "authorNotes": "整体说明：哪些复用模板、哪些为新画",   // 字符串
  "animations": [
    {
      "slot": "skill_ready",
      "purpose": "释放技能前的姿势",
      "includesCompanion": true,                        // true/false/"" 
      "companionNote": "仅开大时出现两只召唤物"
    }
  ],
  "effects": [
    {
      "origin": "reuse",                                // reuse/reskin/original/""
      "originNote": "复用凉月官方召唤特效；仅换主色"
    }
  ],
  "uiDeclarations": {
    "base:skill_cutin": { "autoCrop": false, "mask": "none", "note": "需出现召唤物，禁止自动裁切" },
    "base:battle_control_board": { "autoCrop": true, "mask": "cone", "note": "" }
  },
  "voiceDeclarations": [
    { "file": "voice/ally/join.mp3", "entry": "ally", "usage": "join", "text": "……", "reused": false }
  ]
}
```

字段与取值建议：

- `uiDeclarations[form:slot].mask`：`auto`（默认）/ `none` / `rounded` / `cone`（技能指引）/ `hexagon`（技能连锁）/ `circle`（队员状态）；
- `voiceDeclarations[].entry`：`ally` / `battle` / `home` / `login` / `words`；
- 兼容性：schema 保持 `starpoint-character-studio-v1`，新字段全部可选，读取时缺省为“未标注”；只在保存时写回，不改旧文件。

### D2 包内 README 从 `交接说明.txt` 升级为 `README-稿主必读.md`

建议由工坊在导出 `.wfchar.zip` 时自动生成，内容结构：

1. 这个包是什么、怎么在工坊里打开；
2. **动作清单表**（自动带出）：槽位 / 中文 / 帧数 / 播放方式 / 包含召唤物 / 说明；
3. **语音入口表**（自动带出）：文件 / 入口 / 用途 / 台词；
4. **UI 用途声明**：五类重点用途的取景与遮罩意图；
5. **特效来源声明**：复用 / 重皮 / 原创；
6. **未标注项清单**：当前仍为空、需要作者补的字段（逐条列出）。

这样即使别人接手或跨工具迁移，也能不看 JSON 就知道“每套帧对应哪个状态”。

## 5. 改动点 E：制作方发布 preflight（`wf_character_flow preflight`）

对应实现：`tools/fantasy-gauntlet-mod-tools/wf_character_flow.py`（`preflight` 命令）、`wf_character_pack.py`（`PreflightReport`）、`tools/character-studio/core/wf_character_requirements.py`（37 项硬门 + master 引用门禁）。

### E1 时机

`preflight` 阶段（发布前、生成候选包之前）；报告写入既有 `preflight` 字段，不新增流程。

### E2 显示内容

在现有“文件是否存在”之外，增加一个 **来源与声明（source & declarations）** 分组，逐条按“问题 / 位置 / 怎么改”输出：

```text
[warning] 基础状态引用了合成帧
  位置：pixelart 序列 neutral（2 个 tick）
  说明：素材带 _sp 合成帧标记，动作声明 includesCompanion 为空或 false
  改法：确认设计后改作者声明，或替换为纯本体帧后重跑 preflight

[warning] 获取演出未声明附属物
  位置：pixelart 序列 special_land / special_pose
  改法：在工程动作说明中二选一填写“带/不带召唤物”

[warning] UI 用途未声明遮罩
  位置：ui/battle_control_board_0（技能指引）
  改法：确认采用官方锥形遮罩，或标记 none 并说明
```

### E3 判定建议

- 保持现有 37 项“文件存在性”硬门不变；
- “声明缺失”默认 **warning、不阻断 release_ready**，但必须在报告中列出，并计入交付记录；
- 仅当“基础状态引用合成帧且声明为 false/空”且该状态属于基础 8 槽时，建议**升级为阻断**（这是已经出过线上事故的组合）。

## 8. 验收建议（代码合入后）

1. 用凉月作者包做回归：导入时应提示“104 组同名纯本体/合成帧”，基础态动作卡显示“疑似合成帧”，检查页出现对应 warning；
2. 把 `skill_ready` 标记“包含召唤物=是”后，warning 消失、不再误报；
3. 导出 `.wfchar.zip` 应包含《README-稿主必读.md》，动作清单表与工程内容一致；
4. 发布 preflight 对同一工程输出“来源与声明”分组，基础态合成帧未声明时给出阻断结论。
