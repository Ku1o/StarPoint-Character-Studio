# StarPoint CN 稿主资源提供指南

面向：为自制角色提供美术、动画、特效、音频素材的稿主。
目标：一次说清“交什么、怎么命名、放哪里、在游戏里用在哪、哪些必须有”，避免“素材给了但被用错地方”。

这份指南不要求你理解游戏打包、图集、压缩格式或版本号。凡是“制作方可以从母版或模板自动生成”的内容，都已在文中标注，不需要你重复制作。

---

## 0. 开工前先做三件事

1. **先要一个“角色专用参考包”**。不同角色的动作数量、帧数、图集尺寸和语音槽位并不相同，不要照着别的角色的文件名硬套；请让制作方先导出目标角色的只读参考包。
2. **按本指南和《稿主素材包最小模板》整理素材**（见 `04-稿主素材包最小模板/`），一次性放对目录和文件名。
3. **交付时同时附上两份文字**：`00-需求单.md`（要做什么）和 `01-提交前自检清单.md`（逐条勾过）。没有文字说明的素材包，制作方只能靠猜，最容易被用错。

---

## 1. 资源总览：什么是必须的，什么是可选的

| 类别 | 是否必须 | 在游戏里用在哪 | 你要交什么 |
| --- | --- | --- | --- |
| 立绘母版（基础 + 进化） | **必须**（明确声明复用模板时除外） | 角色详情大图、主城立绘、以及所有小图/头像/缩略图的裁剪源头 | 两张透明全身母版，见第 3 节 |
| 像素动画帧组 | **必须**（复用模板动作或只换配色时除外） | 战斗中的小人动作、获取演出 | 按状态分目录的逐帧 PNG，见第 4 节 |
| UI 裁切图 | 可选（默认由制作方从母版派生） | 图标、编队、技能插入图、技能指引、技能连锁等 | 只有“必须特殊构图/表情/文字”时才单独给，并写明用途 |
| 技能场上特效 | **必须做出选择** | 主动技能释放时的场上表现 | 三选一：复用某角色 / 重皮（给模板+配色） / 完全原创（给四件套或骨架），见第 5 节 |
| 技能音效 | 可选 | 技能施放、命中、蓄力等时点 | 标准音频文件 + 说明“哪个动作第几帧响” |
| 角色语音 | 可选（没有配音的角色请写明） | 加入、进化、战斗、主页问候 | 按入口分类的音频 + 台词文本，见第 6 节 |
| 剧情表情、剧情横幅 | 可选 | 角色剧情 | 只在有剧情需求时提供 |

> 一句话原则：**改动了的才交，没改动的写“复用”。** 不要为了“看起来完整”把模板角色的整套资源复制一遍。

## 2. 目录与命名规范（通用规则）

推荐直接使用最小模板里的目录结构：

```text
角色名-素材包/
├─ 00-需求单.md
├─ 01-提交前自检清单.md
├─ masters/            # 立绘母版
├─ pixelart/           # 像素动画，一个状态一个子目录
├─ effect/             # 技能特效源素材与声明
└─ voice/
   ├─ ally/            # 加入 / 进化
   ├─ battle/          # 战斗语音
   ├─ home/            # 主页语音
   └─ 语音对照表.csv
```

命名规则（建议全部遵守）：

- 文件名只用 **中文、英文字母、数字、下划线、连字符**，不要用空格、括号、`#`、`&` 等特殊符号；
- 一个动作一个目录，目录名与动作状态名一致（如 `neutral`、`walk_front`、`skill_ready`）；
- 帧号统一三位数从 `001` 开始（`neutral_001.png`、`neutral_002.png`…），保证按名称排序就是播放顺序；
- **纯本体帧不带任何后缀**；带召唤物/附属物/额外元素的合成帧必须带清晰后缀（推荐 `_sp`），并且**单独放一套文件或单独目录**；
- 同一个动作的所有帧使用**相同画布尺寸和相同脚底位置**，不要有的帧大有的帧小；
- 不要预先拼成一张大图再拆着交（可以整张精灵图 + 说明切片方式，但优先交逐帧 PNG）。

## 3. 立绘与界面图

### 3.1 立绘母版（必须）

`masters/base.png`（基础形态）与 `masters/awake.png`（进化形态）：

- 透明背景的 **RGBA PNG**，分辨率不低于 **1440×1920**；
- 完整全身，人物、武器、衣摆、飘带都不要被画布裁断；四周建议留出少量透明边；
- 两张图必须是同一角色，脸型、发色、服装关键特征保持一致；
- 不要预先缩放、不要加白色底、不要把多个人物合在一张图里；
- 如果只有一张母版、进化形态暂时复用，请在需求单中写明“进化沿用基础”。

有这两张母版，制作方就可以自动派生下面所有界面图。**默认不需要**你交二十多张裁切小图。

### 3.2 界面图用在哪（派生关系）

游戏中每个界面直接读取对应的图片文件，用途固定：

| 用途（文件后缀） | 尺寸 | 游戏中的位置 |
| --- | --- | --- |
| `full_shot_1440_1920_0/1` | 1440×1920 设计画布 | 角色详情大图、主城立绘、插画切换第 6 面板 |
| `square_0/1` | 212×212 | 角色图标、插画切换「图标」面板 |
| `square_132_132_0/1` | 132×132 | 小尺寸方形头像 |
| `square_round_95_95_0/1` | 95×95 | 小圆角头像 |
| `square_round_136_136_0/1` | 136×136 | 大圆角头像 |
| `thumb_level_up_0/1` | 252×329 | 升级 / 强化界面立绘卡 |
| `thumb_party_main_0/1` | 186×392 | 队伍编成主位 |
| `thumb_party_unison_0/1` | 144×188 | 队伍编成副位（合击位） |
| `battle_control_board_0/1` | 104×268 | 战斗下方技能栏立绘（技能指引） |
| `battle_member_status_0/1` | 58×58 | 战斗队员状态小头像 |
| `cutin_skill_chain_0/1` | 276×319 | 技能连锁 cut-in |
| `skill_cutin_0/1` | 1024×512 | 技能演出插入图（战斗横图） |

### 3.3 五个重点面板：构图不对会被一眼看出来

插画切换设定里有五个面板直接读上面的图片，**它们不是简单缩放**，取景要与官方同类用途对齐：

| 面板 | 读取的图 | 正确构图 |
| --- | --- | --- |
| 图标 | `square_*` | 脸部特写、铺满画布（不要全身远景） |
| 队伍编成 | `thumb_party_main_*` | 头 + 胸 + 腰线，铺满画布（不要上下留大片透明） |
| 技能插入图 | `skill_cutin_*` | 宽幅半身动作构图，铺满画幅 |
| 技能指引 | `battle_control_board_*` | 竖向头胸条，铺满画布 |
| 技能连锁 | `cutin_skill_chain_*` | 脸部特写 |

如果你希望某个用途使用**特殊表情、特殊姿势、文字或额外元素**（例如技能插入图要出现召唤物），请：

1. 单独提供那张源图，并在文件说明中写清对应用途；
2. 在需求单中写“**该用途禁止从母版自动裁切**”，并注明取景要求。

否则制作方会统一从母版按官方构图自动裁切。

### 3.4 形状遮罩（重要）

部分界面图在游戏中是**带形状边框**的，形状烘焙在图片的透明通道里：

| 用途 | 形状 |
| --- | --- |
| 技能指引 `battle_control_board` | 冰锥/水滴形（上宽下窄） |
| 技能连锁 `cutin_skill_chain` | 六边形 |
| 战斗队员状态 `battle_member_status` | 圆形 |
| 圆角头像、升级卡、编队缩略图 | 圆角矩形（各类半径不同） |
| 图标 `square` / `square_132_132`、技能插入图 `skill_cutin` | 纯矩形（不加遮罩） |

默认由制作方按官方形状自动烘焙（推荐）。请注意：**形状会裁掉框外的像素**，所以构图不要把重要内容贴到画布边缘。

如果你自己绘制了形状边框，请在需求单中写明“使用我提供的形状”，并把形状说明清楚（外接尺寸、圆角半径或形状名称）。

## 4. 像素动画（战斗小人）

### 4.1 游戏需要哪些状态

战斗小人按“槽位”播放，默认需要 9 个普通动作 + 2 个特殊动作：

| 槽位名（目录名） | 中文 | 组 | 播放方式 | 说明 |
| --- | --- | --- | --- | --- |
| `neutral` | 待机 | 普通 | 循环 | 平时站立，也是检查整体造型的基准 |
| `walk_front` | 向前移动 | 普通 | 循环 | 游戏内半速播放 |
| `walk_back` | 向后移动 | 普通 | 循环 | 游戏内半速播放 |
| `skill_ready` | 技能准备（开大） | 普通 | 播放一次 | 释放技能前的姿势 |
| `kachidoki` | 胜利 | 普通 | 循环 | 战斗胜利庆祝 |
| `into_coffin` | 倒下 | 普通 | 过渡 | 失去战斗能力 |
| `ghost_raise` | 灵魂出现 | 普通 | 过渡 | 倒下后灵魂出现 |
| `ghost_neutral` | 灵魂待机 | 普通 | 循环 | 等待复活期间 |
| `revive` | 复活 | 普通 | 播放一次 | 复活回到战斗 |
| `special_land` | 获取·登场 | 特殊 | 过渡 | ★4 以上角色获取演出的登场段 |
| `special_pose` | 获取·定格 | 特殊 | 播放一次 | 登场后的展示姿势 |

可选（按设计需要添加）：`attack_initial` 攻击起手、`attack_charge` 攻击蓄力、`attack_action` 攻击动作、`attack_fire` 攻击释放、`wince_ready` 受击、`stun_ready` 眩晕、`dead` 死亡姿势。

### 4.2 每个状态必须写清的六件事

在 `pixelart/动作说明.md` 中，对每个状态写：

1. **名称与用途**（这个动作在什么情况下播放）；
2. **帧数**（一共几张）；
3. **帧顺序与每张停留时长**（例如 6、12、6 帧）；
4. **循环方式**（循环 / 播放一次 / 停在首帧 / 衔接下一段）；
5. **定位方式**（脚底对齐还是画面中心对齐）；
6. **是否包含召唤物/附属物**（见下一条，最重要）。

### 4.3 基础状态请提供纯本体帧（本次事故的直接原因）

- `neutral`、`walk_front`、`walk_back`、`kachidoki`、`into_coffin`、`ghost_raise`、`ghost_neutral`、`revive` 这些**基础状态，请提供不含召唤物、不含附加特效的纯本体帧**；
- 如果你也为这些状态画了“本体 + 召唤物”的合成帧，请**单独放一套**（推荐文件名加 `_sp` 后缀），不要和纯本体帧混在同一目录里直接导入；
- 出现规则要让制作方知道，例如：“两个召唤物只在开大（`skill_ready`）时出现”或“战斗全程都在”；
- 请不要把两种帧当成同一套交，也不要只交合成帧让制作方去猜哪个是本体。

已经发生过一次真实事故：作者每个动作都交了两份素材（纯本体 + 合成），工程里所有动作都指向了合成帧，导致待机、移动、胜利、倒下全部带着召唤物。**每交一套合成帧，都要在动作说明里写清它对应哪个状态。**

### 4.4 获取演出（`special_land` / `special_pose`）要单独说明

获取演出用不用召唤物、用不用额外特效，**必须明确写出来**，二选一：

- “获取演出带召唤物”：请把这两个状态的合成帧单独提供；
- “获取演出不带召唤物”：请提供纯本体帧，或写明允许制作方按纯本体处理。

没有说明时，制作方只能自行决定，之后返工成本很高。

### 4.5 画布与格式要求

- 单帧 PNG，透明背景，单边不超过 1022 像素；
- 同一动作所有帧画布一致、脚底（或中心点）位置一致；
- 不要预先放大（不要放大 4 倍、6 倍再交）；
- 不要交 PSD、GIF、APNG、视频；请导出逐帧 PNG；
- 如果用整张精灵图交付，请附切片说明（单格宽高、留白、间隔、行列顺序）；
- 不知道从哪个尺寸开始时：优先与模板角色同动作的实际画稿尺寸一致。

## 5. 技能特效与音效

### 5.1 场上特效必须三选一

像素目录里的 `skill_ready` 只是“技能蓄满”的动作；主动技能在战场上还有一个独立的特效，必须明确来源：

1. **复用**：写明复用哪个角色（或哪个官方特效），最省素材；
2. **重皮**：写明模板特效 + 目标配色/纹理参考，动作与时序保持模板不变；
3. **完全原创**：提供可用四件套（贴图 PNG、图集、parts、timeline），或指定一个可复用的骨架并提供与其格子对应的新贴图。

只交概念图、GIF 或一段视频**不足以**制作全新的特效；如果只想提供视觉参考，请写“仅供参考，允许制作方另行实现”。

### 5.2 音效

技能相关音效请按用途标注，并说明触发时点：

- 用途：施放 / 命中 / 蓄力 / 移动 / 其他；
- 时点：绑定在哪个动作、第几帧响起、是否需要循环、是否需要淡出；
- 格式：标准可播放的 WAV / MP3 / OGG 均可，不需要自行转码；
- 如果沿用官方音效，写明“复用某个音效”，不需要重复提供文件。

## 6. 语音与台词

### 6.1 按三个入口目录分类（重要）

```text
voice/
├─ ally/     # 加入 join、进化 evolution
├─ battle/   # 战斗开始 battle_start、技能喊声 skill、技能就绪 skill_ready、
│            # 强化弹射 power_flip、落穴 outhole、胜利 win 等
└─ home/     # 主页问候语音（可多条）
```

另有可选的 `login/`（登录语音）与 `words/`（剧情语料）；剧情语料不属于普通角色换包的必需项，只有剧情明确用到时才要。

### 6.2 每条语音都要有对照行

请填写 `voice/语音对照表.csv`，每条一行：

| 文件 | 入口分类 | 用途 | 台词文本 |
| --- | --- | --- | --- |
| `ally/join.mp3` | ally | 加入 | 我在加入时说的台词…… |
| `battle/win_0.mp3` | battle | 胜利 | …… |
| `home/home1.mp3` | home | 主页问候 | …… |

- 文本用于登记游戏内字幕/台词表；没有文本的语音只能当素材，不会被自动猜词；
- 语音请确认已获得使用授权，尤其是非本人声线；
- 格式：WAV、FLAC、高质量 MP3 均可；制作方负责转成游戏需要的编码；
- 沿用模板语音、只替换其中几条时，请写明“其余复用模板”。

## 7. 剧情、表情与横幅（可选）

只有明确要做角色剧情时才提供：

- 剧本文字与出场顺序；
- 需要的表情原图（透明 PNG）；
- 剧情横幅源图。

不需要剧情的话，请不要提供 `words`、`story` 一类目录。

## 8. 打包与交付

把最小模板复制一份，按目录放好素材，并保留两份填好的文字：

```text
角色名-素材包/
├─ 00-需求单.md              # 填好的需求单
├─ 01-提交前自检清单.md      # 已逐条勾选
├─ README-素材清单.md        # 建议：本次交了哪些、哪些复用模板
├─ masters/…
├─ pixelart/…（含 动作说明.md）
├─ effect/…（含 特效声明.md）
└─ voice/…（含 语音对照表.csv）
```

交付前请删除模板中的 `_命名说明.txt` 等占位文件，压缩为一个普通 ZIP，文件名建议 `角色名-素材包-日期.zip`。

## 9. 常见错误对照表

| 常见做法（容易出问题） | 正确做法 |
| --- | --- |
| 每个动作同时交纯本体帧和合成帧，但没有说明 | 基础状态只交纯本体；合成帧单独放、单独命名 `_sp`，并在动作说明写明对应状态和出现时机 |
| 全部动作都用“本体 + 召唤物”的合成帧 | 待机/移动/胜利/倒下/灵魂/复活等基础状态必须用纯本体帧；召唤物只在明确的状态出现 |
| 获取演出是否带召唤物没写 | 在需求单里二选一写明 |
| 只交全身母版，却希望图标/指引是脸部特写 | 默认可自动裁；若要求特殊构图，请单独给图并注明“禁止自动裁切” |
| 派生小图上下有大量透明边、人物偏小 | 交给制作方按官方构图重新裁切，或按第 3.3 节说明期望构图 |
| 技能指引/连锁交纯矩形图 | 说明是否需要形状遮罩，默认由制作方按官方形状烘焙 |
| 特效只有概念图或 GIF | 选择“复用/重皮/原创”，原创需四件套或骨架 |
| 语音没有分类、没有文本 | 按 ally/battle/home 分目录，逐条填对照表 |
| 交了一堆模板里本来就有、没有改动的资源 | 没改动的写“复用”，只交真正改动的内容 |

## 10. 制作方会替你完成的事（不需要你操心）

- 新角色 ID、内部代号、资源路径与补丁编号；
- 图集拼接、压缩、平台纹理（Android / iOS）生成；
- 从两张母版派生全部界面小图与遮罩；
- 打包清单、版本号、校验文件、服务端/客户端接入；
- 语音转码、响度处理与游戏内封装。

你只需要把**只有你能提供的内容**（原画、拆帧、音频、文字说明）按本指南准备准确。
