# 原稿接收与制作交接

这些功能在现有作者填写包、素材导入、检查与交付页中使用。工程仍采用 v1 格式；新增字段可选，旧工程缺字段时显示未标注。这些功能纳入 0.8.2 预览版，配套 Windows 工具通过 [v0.8.2 版本入口](https://github.com/Ku1o/StarPoint-Character-Studio/releases/tag/v0.8.2)与 [Windows ZIP](https://github.com/Ku1o/StarPoint-Character-Studio/releases/download/v0.8.2/StarPoint-Character-Studio-0.8.2-Windows.zip)获取。完整技能、特殊形态、召唤、动态依赖和游戏实战仍需另行验收。

## 稿主从这里开始

1. 在「角色制作包」表达角色、技能和美术意图。资源清单逐项选择自己提供、明确复用、由制作方派生、不适用或申请协助，并写明理由和参考。
2. 在原稿接收区上传收到的原始 ZIP，填写作者与使用授权。原 ZIP、成员原路径、原始字节 SHA-256 与制作后素材分开保存；历史原包找不到时如实记录缺失。
3. 上传母版，关联原稿来源。详情头像、缩略图等可从母版派生，无需把每张派生图都重新画一遍。像素导入后填写动作用途、源画布、身体与足底位置、时长、循环和返回状态；未知的游戏 selector 交给制作方核对。
4. 声音选择自录、复用或无配音；自录语音补台词全文与实际入口。未提供素材、坏关联和空入口/台词会分别提示，不会仅因选择“已提供”就完成。
5. 在「检查与交付」看作者待补和制作方待核，导出工程、填写表与 README。稿主只需说明创作意图，游戏 ID、DSL、封装、资源版本与原生验收由接入方完成。

可直接使用[准备指南](author-experience/01-稿主资源提供指南.md)、[自检清单](author-experience/02-稿主提交前自检清单.md)和[填写目录](author-experience/starter-pack/README.md)。界面状态、导出填写表与生成 README 共用制作填写包规则，明确复用或无配音不会变成虚假作者缺项；接入尚未完成仍保留制作方待核。

## 来源和动作

`sourceIntake` 保存原包、原成员和派生关系。原始文件存于工程的 `sources/`，原 ZIP 存于 `sources/packages/`，不以重编码 PNG 的 hash 代替原稿身份。参考包导入同样保留收到的 ZIP；裁片和 atlas untrim 关联真实原图、atlas、矩形与变换。原稿清单不可通过普通编辑器重写，导出、导入和工程迁移验证原始字节及 ZIP 成员关系。

`actionContracts` 是作者动作说明，和实际帧清单同时交付。源格号从零开始，保留跳过透明格后的真实位置；身体与足底锚点、60Hz 时长、循环、恢复动作和用途分别填写。槽位名称不会自动证明详情初始化、战斗初始化或再次施放的 selector。制作方将 selector 标为核实时，需提供值、场景和依据。

## 整角色审计和技能预览

检查页可填写 `characterAudit`：main/unison/leader、形态与 switch、能力/召唤/PF/公共依赖、UI 和独立 cutin，以及各请求者、来源、collection 与 layer。编译后报告回读实际整张 PNG，面积按 `(ceil(w)+2)*(ceil(h)+2)` 计算。仅在声明的同一桶、collection、layer 内按逻辑来源复用，跨桶不全局去重；UI/cutin 不混入战斗层。

parts 类型、预建实例与每 tick 叶命令单独统计，均不代表 GPU draw calls。缺失范围或完整语义依赖仍显示 unknown；面积可接受也不证明形状能装入原生图集。任意阵容装箱与原生运行验收另验。

检查页的「自动无损优化与依赖闭包」供制作方使用。先点击编译对比；这一步不保存配置、修改原稿或增加工程 revision。确认后启用后续编译，也可恢复原布局，支持撤销、重新打开与工程往返。`atlasOptimization` 是可选配方，默认关闭以兼容旧工程；`enabled` 必须为布尔值，其余有界预算可在高级配方中调整，未知扩展字段保留。

优化器仅搬运同一 PNG 的完整图块，不裁透明边、不缩放、不旋转、不改逻辑名称，也不跨桶合并。先序列化，再验证 RGBA 全字节（含透明像素 RGB）、除 x/y 外完整 atlas 元数据、frame/parts/timeline 原字节，以及所有可支持组的逐 tick 变换、颜色、混合、通道和叶命令顺序。音频、DSL 和其余非图集文件保持字节相同。面积必须严格改善且宽高均不增大，才能采用；坏引用、未知语义、无改善或预算超限会保留原图并列明理由。图集查看、图块导出和编译回读预览使用相同开关。

`character_dependencies` 递归解析冻结资源根、已保存技能版本及条件/回调分支、原生 kind2 嵌套 parts、atlas 到整张纹理，以及 timeline 到声音。请求者、来源、角色/形态/switch、bucket/collection/layer 分开保留；固定缺引用、动态路径、未知语义与范围缺口分别报告。参考声音仅采用 `audio_catalog` 明示的逻辑路径映射。`dependencyScope` 可声明有限根与范围，声明或一个资源 hash 都不能自动证明整角色原生语义完整。

依赖诊断入口允许未完成草稿先查看参考来源。若编译门禁失败，报告保留 `compiledCoverage.status=unavailable` 与原错误；不会填默认能力值、删掉原生行或把视觉子集当整工程通过。`compiledResourceClosure` 只表示所选冻结资源图，`characterSemanticClosure` / `completeCharacterTotal` 目前保持 false：完整能力、召唤、PF、公共/UI 等原生域提取器尚未齐全，main/unison/leader 与形态/switch 根需继续核验。有限固定引用缺失为 0 不代表完整语义缺失为 0，后者保留 null。

编译产物另附 `图集无损优化.json`、`角色依赖闭包.json`，整角色审计嵌入两份报告。结果描述的是本次工坊生成物；保留工程离线对比不自动替换此前交付的生产图集，也不代表 GPU 性能改善。

优化目标是整张纹理的含边距面积，不保证 PNG 压缩体积下降。图块重新排列可能降低压缩率；报告同时记录前后文件字节，制作方需按实际传输需求取舍。启用后的预览复用完整工程的累计预算选择，单图不得重新计算另一份布局。

技能页显示作者画布、锚点、parts scale 与坐标依据。未声明转换不猜原生坐标；已知无效 `HideCharacter(-18)` 会警示并保留 deferred。`-17` 的素材隐藏预览、手工编排、normal→cast→restore 的离线锚点对照都不代替原生命中绑定、伤害或再次施放验收。

## 声音与获取台词

声音页可分别配置语音与 SFX 的 `audioProfile`。完整解码检查 LUFS、true peak、原通道削波、时长和编码 padding；参考与候选统一 mono，stereo 明确按 `L/2+R/2` 折声道，避免裸比声道数量。目标响度默认未填写，不采用通用角色配额。

测量需要本机可调用 FFmpeg 与 FFprobe；缺少工具会报告未测，不能标通过。生成 CBR MP3 候选需先明确目标和真峰上限，保留原声与处理关系，确认绑定后才应用。编译封装会解码编码后音频复测；完整台词、听感和实际原生声音路径另验。

获取气泡保存 `entryLayout.original` 与独立候选，提供换行/字词差异、估算边界和稿主确认。去掉手动换行仅修改候选；字词变化会提示待稿主确认，也可先保存未确认候选，交接采用前需确认。保存不会覆盖语音原文。当前字体、气泡和换行算法是近似预览，字符数与行数不是通用上限，首次 NewEntry 仍需原生验收。

## 可佩戴铭牌

`degrees` 是可选集合，与 `identity.title` 角色头衔独立。每款保留 320×50 RGBA 成品、完整文字效果层 `letteringAsset`（含描边与阴影）、可选框层、真实内框安全区依据和实际 160×25 缩小预览。安全区遮罩的 Alpha>0 表示整个像素格允许；框饰不算文字，没有安全区或分层依据时保持待核，不自动剪裁原图。游戏 ID、排序、奖励、资格、事务、持有幂等、存档以及列表/佩戴验收由接入方完成。

## 交付和验证边界

工程导出含原稿 bytes、映射、作者填写包、动作/声画声明、生成指南和未覆盖事项；离线编译附整角色、声音、获取排版与铭牌报告。未知字段继续保留，普通只读打开不写回，首次修改保留旧记录，未来格式拒绝写入。报告保持 `gameReady=false`，不会因保存、编译或导出成功自动变成游戏验收通过。

开发回归入口：`python -m unittest discover -s tests -p "test_*.py"`。浏览器测试使用环境已有的 Playwright 与 Edge；原生游戏与 Windows 分发验收单独进行。
