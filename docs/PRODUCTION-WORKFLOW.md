# 新角色生产流程

本工具把作者能理解的角色设计资料和制作方需要核对的技术资料放在同一份工程里，但两者分区保存。作者填写自然语言和资源需求，制作方再填写原生机制、编码、图集和客户端限制；空白项会显示为待补或待核验，不会自动变成“已完成”。

从官方参考包建立工程时，工具会把实际已导入的立绘、UI、动作和语音回填为“已提供”，把可读取但尚未完成用途分类的复杂特效标为“待核验”；这两个状态都不会代替制作方的实战确认。

## 六个交接阶段

1. **作者填写包**：角色名、称号、属性、职责、种族、进化前后形态、基础成长、队长/队员定位，以及主动技能、PF、能力 1–6 的自然语言描述。
2. **制作方核验**：把描述拆成触发条件、对象、范围、段数、倍率、持续时间、冷却、状态/图标要求，标明原生支持、需要客户端适配或待核实。ActionDSL、乘区、底层枚举只出现在核验区。
3. **资源制作**：按清单制作进化前/后立绘、详情/缩略图、像素小人帧、主动技能和 PF 帧集、图标、图集与声音。记录实际显示尺寸、透明背景、帧数、压缩、图集尺寸和同时在场预算。
4. **数据 / DSL 实现**：分开核对显示文案和执行数据；保留官方图表化描述结构，不把技术说明直接写进角色文案。
5. **本地练习战验收**：技能预览不等于实战。固定使用练习战、正确测试队伍和自动战斗，记录目标阵容、退出后的活动记录恢复、H400、C3212 与存档错误的区别。
6. **发布整合**：记录资源补丁起止版本、实际胜出资源、未完成项和回退信息。本地高版本 CDN 与正式云服 1.4.115 发布链分开。

## 清单中的稳定防错项

- 弹道优先复用辨识度高的官方弹道，再做安全的颜色/材质调整；弹道和命中特效分开验收。
- 不默认制作高速场景中难以辨认的小月光 PF 装饰；优先使用方向明确的拖尾、命中反馈或场地扩散。
- 能力、直击、PF、技能伤害入口逐项标记原生支持、需客户端适配或待核实，不能从技能入口推断其他入口也存在。
- 进化前后资源与主城语音成对检查。普通 MP3 放入 CDN 不代表游戏音频封装正确，最终编码/封装必须记录并回读。
- 检查立绘/插画空白、详情尺寸、白背景遮挡像素腿、黑底状态图标、月行独立图标、隐藏增益时长、PF 延长/重置、命中特效辨识度和图集预算。

## 交付文件

「角色制作包」页只导出 JSON 交接资料，不含二进制素材或账号信息；「导出工程」仍包含可编辑素材和旧版字段。`.wfchar.zip` 导入后会保留 `productionBrief`，旧工程没有该字段时自动补版本，并从既有角色设定、技能文字和旧能力描述预填作者页；原始 JSON 只有在下一次成功保存时才写入新字段。

正式发布前仍需制作方完成资源补丁、客户端适配、存档兼容和练习战验收；工具不会把填写完成误报为游戏可发布。
